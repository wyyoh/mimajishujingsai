# 04｜业务数据与统计口径必须固定

## 4.1 主场景与数据集

数据集命名`SYN-120-V3`：A、B两个实验区域，每区60个逻辑节点；其中居民24个、工商业20个、充电设施16个。共120个节点、4个连续15分钟窗口、480个节点窗口值。[D1，第3节]

默认任务选择区域A的居民与充电设施，共40个目标节点。输入为区间平均有功功率，整数单位W，首版非负。用户看到kW时只做有明确单位的显示换算。4个点不足以支持光滑预测曲线，采用阶梯线或明确的离散折线，不虚构中间采样。

合成数据必须有`dataset_id`、生成脚本、种子、记录数与摘要。数据种子用于复现负荷值；密码随机数绝不能使用同一个固定种子。真实数据接入前另行登记许可与脱敏范围。

## 4.2 不允许提前把非目标节点筛掉

每个任务应让源侧为整个120节点样本集生成报告，由GW真正执行PFDAM选择。源侧只接收任务公共上下文，不接收用于预筛选的授权类别；浏览器也不根据明文求和。

默认情境的每窗预期为：

| 情境 | GW收到 | 授权目标有效 | 其他未通过联合检查 | 目标覆盖 |
|---|---:|---:|---:|---:|
| 正常 | 120 | 40 | 80 | 40/40 |
| 修改1份目标报告的窗口 | 120 | 39 | 81 | 39/40 |
| 20%目标节点缺报 | 112 | 32 | 80 | 32/40 |

此表是确定的测试输入与预期，不是已测结果。正常情况下80份未纳入报告并不等于80次攻击：它们可以是不符合授权标签的正常报告。缺报情境是“目标群体20%缺报”，不是全体120节点均匀缺报。若选用另一缺报口径，必须改数据清单、界面说明与预期值，并记录决策。

## 4.3 独立真值不能只检查“对接受集合求和”

单独维护实验真值程序，它从源侧私有数据、任务语义和故障注入计划独立计算预期参与集合；不调用GW的匹配函数，也不读取GW返回的统计值作为答案。

必须同时满足两项断言：

1. 实际接受报告集合与实验预期有效集合一致；
2. 恢复结果等于预期集合的整数和。

仅对GW自行报告的接受集合求和，会使“错误地全部拒绝、结果为0”的实现也通过。这是必须防止的假正确。报告摘要到源节点的映射只放在隔离验证器中，不放在GW、普通前端或公开导出中。

## 4.4 边界输入

没有有效报告显示“无有效数据”；存在合法零值报告显示“有效统计为0”。重复原字节报文不重复计数；迟到报文不修改已发布快照。换区域、类别、窗口、模式或参数都产生新任务和新运行。

每窗`expected_target_count`来自UC审批配置或实验清单；未知时覆盖为`null`。签名后的GW计数只是声明，不自动等于对恶意GW的完整性证明。报告数量不等于可验证的物理设备唯一数。

测量时间窗口与执行时刻分开：历史合成负荷的`slot_start`可以在过去，但证书校验、授权有效期和运行日志使用实际当前时钟。不能靠关闭过期检查使固定日期的样例重新“通过”。

## 5.3 原生适配器怎样控制复杂度

业务角色与其本地密码/通信适配器使用有权限限制的Unix域套接字；每个适配器只挂载本角色密钥。不得建立一个任何进程都能调用、拥有全部秘密的“万能加解密服务”。

L1/L2可以在TLS之上使用简单的长度前缀应用帧，例如4字节大端长度＋UTF-8对象。帧长度先校验，设置合理上限、超时和批量背压。不要自写TLS握手，也不为少量角色通信重新实现HTTP服务器。

适配器需可靠处理部分读写、连接中断和错误返回。构建探针阶段可使用命令行；正式性能测量中禁止每份报告都启动一个新OpenSSL子进程而不计入开销。真实签名与TLS可常驻处理，错误必须上报。

UI接口默认仅监听本机；若对局域网开放，增加实际访问控制与TLS，单独说明其保护范围。浏览器链路不是L1/L2，不能让两条后台链路的绿勾代替全部网络保护。

# 06｜PFDAM内核：先做到真实、正确、可追溯

## 6.1 公式到代码的最小映射

| 工程接口 | 原论文位置 | 验证要求 |
|---|---|---|
| `setup`、`uc_keygen` | V-A、V-B | 参数生成约束、秘密分离、边界条件 |
| `gateway_register` | V-C | GW材料与聚合公钥对应，无角色混用 |
| `authorize` | V-D | 标签集合、多项式系数、令牌维度一致 |
| `generate_report` | V-E | 实际生成CT、B、C、D、T，独立随机量 |
| `match_and_aggregate` | V-F、算法1 | 真实联合检查，只有通过项进入密文聚合 |
| `verify_and_recover` | V-G | 原生回执验证、正确恢复、错误输入拒绝 |

原文实现优化Paillier、配对相关运算、HMAC、授权与掩码处理。[P1] 仅用普通Paillier求和不能自称完整PFDAM；用指数整数模拟群运算、随机字符串模拟密文，也不能进入REAL路径。

接口返回序列化密码对象、验证结果、可公开计数和计时引用；绝不在GW返回或缓存输入明文。SM源侧可以看自己的读数，UC按原协议持有恢复秘密，但实验真值和其他角色秘密不可随意共享。

## 6.2 P0、P1与待核实安全主张

`P0`保存尽可能忠实的论文复现及异常；`P1`保存有明确解释、任务实例化与变更记录的工程内核。四组S0/SA/SB/SAB全部使用同一P1，原生GW签名保持一致。

论文假定TA可信、主要参与方诚实但好奇、GW与UC不串谋。[P1，IV-B] 不能添加ML-DSA后就删除这些假设，也不能因为公开摘要写了某项性质就不再复核。

必须维护`docs/CRYPTO_REVIEW.md`和`claims_registry.json`。每项主张使用独立状态：`PENDING`、`SUPPORTED_WITH_ASSUMPTIONS`、`DEMONSTRATED_LIMITATION`、`REPAIRED_AND_REVIEWED`。一个UI绿勾不等于对所有性质的证明。

## 6.3 必做复核清单

**策略猜测线索。**上传版本中，单标签时可从V、S0与ω0得到：`V / e(S0, ω0) = e(g1,g2)^H(Tag)`。这是一条基于V-B、V-D公式的代数核查线索，不是本手册已经运行的攻击结果。用真实群库核对，区分授权集合隐藏和报告属于集合哪一类的隐藏；检查最终版、原代码与不同标签规模。公开task_nonce不能消除该关系。[P1][D1，第20节]

**H1群类型。**V-A定义的H1值域与V-F/V-G签名配对输入存在需要解释的类型关系。核对是否记号复用、排版错误或需要新的hash-to-group实例；将映射名称、域分离与依据写入实现说明，不能悄悄混用GT和G1。

**恢复公式与参数。**核对原文显示式中的模运算、整数除法与逆元；模数、子群阶、生成元、消息界、掩码的数域必须相容。先获取并研读原文引用[37]的完整优化Paillier构造；目前ACSAC官方页面可核实其论文与子群优化方向，但摘要不能代替完整参数算法。[S14]

**维度与零值。**核对l、l+1、实际标签数、公共参数最大维度、零系数及求逆对象。不要通过重复标签伪造大策略集。不同任务规模可能需要不同参数实例，必须明确param_id和比较口径。

**随机数和预计算。**新报告使用系统安全随机源；预计算项绑定参数与标签、一次性领取并在并发/重启下持久化消费。重传重用同一合法报文字节，不重新随机化后再次统计。确定性随机量仅用于有明确隔离标识的测试向量。

**输入有效性。**对群元素做正确类型、规范编码、曲线与子群检查；按具体密码实例处理无穷远点和单位元，不能一概拒绝数学上允许的零系数结果。校验大整数大小、密文所属域、报告维度和消息累计上界。

## 6.4 参数选择原则

不直接将论文旧参数与旧耗时当作现代部署成绩。工程参数由完整构造要求和实际库能力决定；可以评估现代非对称配对实现，但更换曲线、子群或哈希必须记录，并验证原方案假设是否仍匹配。

RELIC可作为研究型配对实现候选，版本与参数都需锁定。[S12] 不能用“使用了某个库”代替安全级别论证；也不能简单把模数位数加大就宣布整体达到某个统一安全等级。`parameter_manifest.json`至少记录构造来源、各数域与位数、配对族、实现版本、适用范围和未解决项。

## 6.5 发现问题后怎样继续，不怎样掩盖

排版或类型解释由公式推导和测试记录支撑；实质协议变化必须开ADR并进行独立复核。受影响的安全主张暂停发布，但不阻止A/B、界面和独立测试等无关工作继续。

不要为了过审悄悄删除单标签测试，不要把PFDAM替换为另一协议后仍用原名称，不要将未解释性质写成已实现。若发现影响核心机密性、授权选择或正确性的实质问题，应给出最小复现、修正候选及影响范围交用户/导师决策。问题有了证据与解决路径后继续推进，不以“论文可能有问题”为由停止整个工程。

# 07｜任务语义、源侧调度与确定性编码

## 7.1 业务条件到标签

UC支持有限选择：区域A/B、居民/工商业/充电设施、4个窗口。区域与资源类别的AND形成一个复合标签，多标签为OR。不要把`{区域A, 居民}`当作“区域A且居民”。[D1，第7节]

建议标签字符串来自规范编码对象：

```json
{
  "schema": "grid-tag-v1",
  "task_nonce": "独立随机任务标识",
  "slot_id": "该任务的窗口标识",
  "metric_id": "average_active_power_W",
  "region": "A",
  "resource_class": "residential"
}
```

示例只定义字段，不是实际令牌。UC用允许类别生成令牌；源侧用自己的静态属性和公共上下文生成标签，不先过滤节点。任务上下文绑定是本项目实例化增量，必须以跨任务和跨窗口测试验证。

## 7.2 不向GW泄露本来声明隐藏的信息

授权对象不附明文目标标签或可枚举策略的普通哈希。`policy_ref`使用独立随机标识，`token_bundle`只含执行必需材料。GW得到的时段、匹配计数和源服务身份仍可能形成元数据，不能宣传“GW不知道任何信息”。

管理台展示的语义策略位于UC侧。抓包、GW日志、事件流与导出同样检查信息暴露；调试时把全部对象打印出来会破坏角色边界。

## 7.3 JCS、类型与签名字节

外层对象使用RFC 8785 JCS；签名主体与签名数组分开。重复键、非法Unicode、NaN、Infinity和超界数值在规范化前拒绝。大整数用十进制字符串，密码字节用无填充Base64url，时间使用统一UTC格式或明确的整数毫秒，签名后不重新做模糊类型转换。[D1，第8、13节][S9]

JCS不等于简单`sort_keys=True`。应采用通过官方向量的实现或经过互操作验证的受限编码，不自行假定JavaScript与Python对所有数字字符串的语义相同。业务层使用已验证的不可变对象，不能验签后再从另一个请求位置读取令牌或参数。

# 08｜A模块：任务授权与回执双签名

## 8.1 固定配置，不重新发明算法

所有四组模式使用ECDSA P-256/SHA-256保护相同外层对象；A开启时额外使用Pure ML-DSA-65，要求所有必需签名均有效。两种算法使用独立密钥和可信角色登记表。[D1，第8—11节]

ML-DSA上下文固定为`GRID-TASK-AUTH-V1`与`GRID-AGG-RECEIPT-V1`。正式运行启用正常消息编码与随机化签名，不用test-entropy、不把哈希值冒充Pure消息、不使用内部mu模式。OpenSSL提供这些接口和参数，具体调用按采用版本的官方文档实现并测试。[S5][S7]

优先用公开标准测试向量和独立验证路径检查适配正确性。不要自行实现格运算，也不把旧Dilithium实验接口当作ML-DSA标准接口。原论文GW签名仍保留；外层增强不能绕开原生验证。

## 8.2 TaskAuthorization

主体至少含：`object_type`、`schema_version`、`task_id`、`run_id`、`issuer_role`、`target_gw`、`slots`、`issued_at`、`not_before`、`expires_at`、`metric_id`、`param_id`、`policy_ref`、`token_bundle`、`security_profile`、`key_epoch`。

令牌可内联；若分离存储，签名必须覆盖实际使用字节的摘要与长度，并在取回后核对。不要签名URL却使用其随后变化的内容。

验证顺序：尺寸与类型 → 本地期望对象/算法 → 本地可信公钥 → 全部所需签名 → 签发者和接收方 → 有效期 → 参数、时段和安全配置 → 当前任务状态 → 原协议执行。

本地最低安全策略优先于消息中自报的`security_profile`。在SAB端点收到自称S0的对象，即使带有合法经典签名，也不得因此免去ML-DSA验证。

## 8.3 AggregationReceipt

每窗产生回执，绑定`task_id`、`run_id`、`authorization_digest`、`snapshot_id`、`slot_id`、`param_id`、聚合密文、原生GW签名、计数、处理状态、签发时间及必要证据关联。

`input_digest`建议由规范排序的报告摘要列表形成，表示快照关联，不称为聚合正确性的零知识证明。UC验证外层签名和上下文后，再执行原生签名验证与恢复。

幂等以授权主体摘要、任务和快照标识为依据，不仅依据签名比特串；同一有效对象可能有不同随机签名。重复受理返回既有结果或明确拒绝，不再次发布。

## 8.4 密钥和证书不混用

初始化分别生成PFDAM材料、ECDSA对象签名密钥、ML-DSA对象签名密钥、TLS角色证书密钥。可信公钥由本地注册表绑定role/key_id/epoch，不能采用消息随附公钥作为信任根。

旧回执可在可信历史公钥下离线验签，但过期任务不能重新执行。“签名有效”与“当前可受理”分别展示。首版只需可信配置与有限轮换，不开发在线CA平台。

## 8.5 两类验签结果都必须真实

损坏ML-DSA而保留经典签名、损坏经典签名而保留ML-DSA，都必须在SA/SAB中拒绝。不能按OR接受，也不能捕获异常后补发S0请求。合法签名但过期或错接收方的用例，应保留数学验签成功，并在业务检查阶段拒绝。

签名保护来源与受保护字段，不证明物理读数真实、GW诚实或统计一定正确。不得用一次篡改测试宣称实测抵御了量子计算机。

# 09｜B模块：真实业务上的混合后量子TLS

## 9.1 四组配置

| 模式 | 外层ECDSA | 外层ML-DSA-65 | L1/L2允许组 | 业务入口 |
|---|---|---|---|---|
| S0 | 必需 | 不要求 | X25519 | 仅实验 |
| SA | 必需 | 必需 | X25519 | 仅实验 |
| SB | 必需 | 不要求 | X25519MLKEM768 | 仅实验 |
| SAB | 必需 | 必需 | X25519MLKEM768 | 正常默认 |

TLS限定1.3，记录层尽量统一`TLS_AES_256_GCM_SHA384`，经典角色mTLS认证保持相同。0-RTT与会话恢复在主验收中关闭，长连接复用单独测量。参数来自V3，不是本手册新改成另一方案。[D1][S6]

## 9.2 使用真实OpenSSL运行库

构建时固定OpenSSL 3.5系列的已验证修订版，记录源包摘要、编译参数、Provider与实际加载的libssl/libcrypto。不要替换操作系统全局库；使用工程专用前缀或容器镜像。检查C头文件与运行时共享库来自同一构建。

最小原生探针必须完成ML-DSA签名/验签、目标TLS组协商、错误组和错误证书拒绝。命令行探针是依赖放行条件，不是完成L1/L2集成的证据。[S7][S8]

## 9.3 对端身份与应用角色

客户端验证证书链、有效期、目标服务名；服务端要求客户端证书，并将可信身份映射到允许角色。链可信但source证书访问GW管理/回执接口，应拒绝。不要把“证书来自同一CA”当作拥有全部接口权限。

SAB服务的严格策略在首次连接前预置。拒绝不兼容组、错误身份、verify关闭、HTTP明文回退和未保护的旁路端口。若一个实验进程要切换模式，使用隔离端点或重新建立受对应策略约束的连接；不得把旧经典连接继续复用为SB/SAB。

## 9.4 连接证据来自同一SSL对象

`ConnectionEvidence`至少记录link_id、connection_id、进程实例、连接与握手时间、协商版本、actual_group、record_cipher、链验证、身份验证、peer_role、证书签名算法、握手认证算法（可获得时）、session_reused、early_data状态、错误与业务request引用。

实际组使用当前业务SSL连接的API读取，不能从“期望配置”复制。未知字段为`null`；未握手成功不能显示已建立；读取或解析失败不能补成true。OpenSSL的`SSL_get0_group_name()`可读取相关信息，恢复连接的语义需要额外注意。[S8]

适配器生成可信连接标识，应用将真实传输的request与其关联；不能信任远程报文自报的connection_id。保存少量无秘密抓包或双端摘要用于交叉核验，不常驻开启TLS会话密钥日志。

## 9.5 性能与边界

握手字节按实际测量方法记录：区分TLS握手层、TCP/IP层和应用载荷，说明是否计入证书、重传与HelloRetryRequest。使用BIO计数或受控抓包时说明截止边界；不能把ML-KEM公钥长度直接当总握手字节。

B保护链路密钥建立，PFDAM内层仍是经典体系；经典mTLS认证也不自动成为后量子认证。A/B不修复内层策略问题，不承诺对持有内层报文的强量子攻击者的全面安全。[D1，第5节][S6]

# 10｜一条必须先完成的真实纵向流程

在120节点压力测试之前，先运行12节点、2窗口的真实SAB小试跑。它是依赖、角色分工和接口集成的验收，不可用单独的加密示例或握手命令替代。

流程如下：

1. TA初始化，角色进程只加载自己的秘密和可信公开材料。
2. UC创建新任务与运行，编译允许标签，生成PFDAM令牌与双签名授权。
3. GW经L2取得授权，验证实际链路、双签名和任务条件。
4. Source经L1取得公共任务上下文，为全部12节点生成真实报告并提交，不做目标预筛选。
5. GW检查报文、执行PFDAM匹配，形成窗口快照并密态聚合。
6. GW生成原生签名与双签名回执，经L2提交UC。
7. UC检查回执和任务，执行原生验证与恢复，发布群体结果。
8. 验证器独立检查预期接受集合和恢复值；Web显示相应状态和证据引用。

试跑至少有一项合法成功、一次报告修改拒绝、一次错误回执拒绝，以及L1/L2实际组记录。输出`artifacts/probes/vertical_sab_smoke/`，保留命令、退出码、构建摘要、数据说明和结果。

如果论文核心暂时未放行，可以先做A/B与角色通信的独立真实探针，但不得将其标记为上述纵向流程完成。图形开发可并行使用常驻标识的PREVIEW。

# 11｜接口、状态和错误契约

## 11.1 对外业务接口

| 接口 | 行为 | 安全要求 |
|---|---|---|
| `POST /api/runs` | 创建允许模板的SAB任务 | 服务端白名单、请求幂等键、拒绝任意算法/密钥路径 |
| `GET /api/runs/{id}` | 状态、结果与证据摘要 | 仅授权业务可见字段 |
| `GET /api/runs/{id}/events` | SSE或轮询阶段事件 | 单调序号、run绑定、断线后续读 |
| `POST /api/runs/{id}/cancel` | 终止未完成任务 | 不删证据，不修改旧快照 |
| `GET /api/runs/{id}/export` | 下载非敏感运行包 | 白名单导出，不打包整个运行目录 |
| `/lab/*` | 场景注入、四组实验、真值对照 | 单独实验入口与访问开关，非普通业务权限 |

具体HTTP路径属于本手册的实现细化，可在OpenAPI中统一冻结；不可新增任意解密、SQL、shell或远程密钥加载接口。

## 11.2 核心对象

| 对象 | 必须解决的问题 |
|---|---|
| `PublicTaskContext` | 将公共窗口与参数发给源侧，不泄漏授权集合 |
| `TaskAuthorization` | 真正使用的令牌与任务、策略模式一致 |
| `ReportEnvelope` | 规范密码报文、任务上下文、幂等标识，不能带单户明文 |
| `AggregationReceipt` | 绑定本次授权、快照、窗口和聚合密文 |
| `ConnectionEvidence` | 证明消息走过相应实际连接，而不是另一段探针 |
| `RunRecord` | 把版本、执行模式、数据来源、结果、计时与证据连起来 |
| `PublicRunSummary` | 面向Web/导出，不包含敏感授权材料和私有映射 |

Agent先实现JSON Schema或等价强类型模型，再由模型生成接口文档；不要让不同Agent各自发明字段。至少测试序列化往返、跨语言规范字节和错误字段拒绝。

## 11.3 状态机

后台：`CREATED → AUTH_READY → COLLECTING → SEALED → AGGREGATED → VERIFIED → PUBLISHED`；另有`REJECTED / FAILED / CANCELLED`终态。每个窗口单独保存状态，整次运行根据所有窗口得到`COMPLETED / PARTIAL / FAILED`。

页面只需待运行、执行中、已完成、部分完成、未通过/失败。更改条件清空旧指标，创建新ID；事件到达时校验当前run_id，防止上一次请求的晚到结果覆盖当前页面。

`VERIFIED`不能泛指所有安全性质：保存`signature_valid`、`context_valid`、`native_verification_valid`与`oracle_match`等分别有来源的字段。

## 11.4 错误不吞掉，不伪造精确归因

统一错误码，例如`AUTH_SIGNATURE_INVALID`、`AUTH_EXPIRED`、`AUTH_WRONG_AUDIENCE`、`REPORT_JOINT_CHECK_FAILED`、`REPORT_INVALID_ENCODING`、`RECEIPT_CONTEXT_MISMATCH`、`TLS_GROUP_UNAVAILABLE`、`TLS_PEER_IDENTITY_INVALID`、`CORE_OPERATION_FAILED`、`COVERAGE_UNKNOWN`。

不要把所有失败写成网络错误，也不要把合法但不匹配的报告写成攻击。错误包包含run/stage/code、用户可读说明和脱敏证据引用，不包含私钥、堆栈中的秘密或全部原始请求。

## 12.1 视觉基线与基本尺度

保留`references/ui/V2.html`的清爽白底、深蓝结构、青绿色重点和琥珀色提示。不改成黑底地图驾驶舱，不使用霓虹连线、旋转地球、装饰性3D电网或大段滚动密文。V2中的60节点、样例状态和原型提示必须按实际新版本更新，但不能在REAL尚未完成时先删掉PREVIEW提示。[D2]

## 12.2 页面一：协同总览

第一屏只有一个主叙述：“按授权安全统计，让群体数据可信协同”。副叙述交代用于分时负荷分析，不是实时调度系统。

中间用Source→GW→UC横向链路，L1/L2放置明确标签，TA放在辅助关系位置。默认注明“结构示意”；运行时的高亮由后台阶段驱动。PFDAM、ML-DSA、混合TLS各有一行保护范围，不出现一个覆盖所有机制的“全域抗量子”盾牌。

下方三张价值卡：选择性聚合、对象与链路验证、同集合正确性与缺报覆盖。主要按钮只有“进入工作台”和“查看保护范围”。查看范围打开抽屉，说明谁能看到什么和哪些假设仍存在。

## 12.3 页面二：聚合工作台

左侧约280—320px：区域、三类资源、窗口、开始按钮。正常业务固定SAB，四组切换只在实验入口。右侧：执行链路、统计值、有效数量/覆盖、4窗口曲线和安全详情抽屉。

安全面板成对显示“要求／实际”：授权签名、L1组、L2组、身份验证、回执签名。actual未知时显示待获得证据，不显示默认成功。验签或连接失败时高亮所在阶段，并允许展开对应证据，不弹出覆盖全部页面的技术错误。

场景用六个简短标签，而不是增加六张页面。引导模式提供“下一幕／返回正常／查看证据”，讲解者可暂停；不得用固定计时自动切页面。只在运行状态真正变化时做轻微动效，等待时显示阶段和实际已处理数量，不制造假百分比。

## 12.4 页面三：验证与报告

页内三个标签：结果一致性、签名与链路、四组对照。显示最少必要信息，专家深入时再展开原始字段。

结果一致性页在隔离实验模式展示两个断言：参与集合是否一致、统计值是否一致。业务模式只显示经过许可的聚合结果与质量说明，不暴露单户对照。四组图表没有实测数据时显示待运行，不填示例柱形冒充结果。

误差为0不能用没有坐标意义的炫技图，优先使用对齐表格与明确的“一致”状态。性能图表统一单位与轴范围，显示样本数、计时口径和失败次数，支持点击追溯原始记录。

## 12.5 REAL / REPLAY / PREVIEW的产品化处理

模式常驻右上角，不用夸张红色遮挡主视觉，但不能隐藏：

- REAL：真实密码、真实通信；数据可以明确标为合成数据。
- REPLAY：来自已保存的真实记录，显示原run_id、版本、时间。
- PREVIEW：交互设计与合成算术，不产生正式密码/性能记录。

合成数据不等于模拟密码。将“数据来源”和“执行方式”分开显示，能既诚实又避免让专家误以为真实内核只是样例动画。REAL失败保留失败，切换回放需明确操作与标识。

## 12.6 视觉验收不是只看首页截图

每轮视觉迭代执行：启动实际页面→自动操作→截图→查看截图→修改→再截图。Playwright可做截图比较，但自动像素通过不能替代人工检查可读性。[S11]

至少检查1920×1080、1366×768；另检查窄屏不损坏功能。覆盖初始、执行中、正常完成、联合检查失败、缺报、TLS失败、无数据、详情展开、长题名、条件变化和导出状态。

截图回归只允许屏蔽真正易变且与正确性无关的时间戳，不得遮住错误、REAL标识、验签结果和握手组来消除差异。不得每次失败都无审查更新golden图。

顶级展示应做到“白板解释清楚、产品操作顺畅、技术证据随时可展开”。不通过增加页面数量、伪造设备地图或炫酷攻击动画来取代这三点。

# 13｜六类情境与演示脚本

## 13.1 故障注入的位置与归因

| 情境 | 注入位置 | 预期检查层 | 页面不得说什么 |
|---|---|---|---|
| D1 正常/换类别 | 任务选择 | PFDAM匹配与恢复 | 全部数据相加也算细粒度 |
| D2 修改报告 | 报告生成后、TLS发送前，保留原认证量 | PFDAM联合检查 | 网络层拦截等于PFDAM检出 |
| D3 20%目标缺报 | 发送计划省略8个目标节点 | 收集与覆盖、剩余聚合 | 恢复了未上报读数 |
| D4 非法授权 | 改已签字段；另测合法签名但过期 | 签名或业务上下文 | 过期等于签名伪造 |
| D5 非法回执 | 改密文/计数；另测跨任务复用 | 回执签名或任务关联 | 签名证明网关绝无漏算 |
| D6 不合规链路 | 不兼容组、错误证书或角色 | TLS握手/身份验证 | 实测破解或抵御量子计算机 |

D2应优先构造格式与数域仍合法、但认证量不更新的修改，以测试联合检查；非法编码另立用例。不能让场景开关直接写入`signature_valid=false`，必须真的改变对象后调用实际验证器。

实验注入只能在用户控制的本地测试环境运行。不得对公网、电网生产系统或第三方资源发起攻击。任务类型进入白名单，参数不能成为任意代码执行入口。

## 13.2 八分钟完整版（内部彩排建议）

| 时段 | 操作 | 一句关键讲解 |
|---|---|---|
| 0:00—0:45 | 总览与角色范围 | 我们交付的是安全统计能力，不是完整虚拟电厂 |
| 0:45—2:00 | SAB真实正常任务 | 看实际报告生成、两段连接、选择与恢复 |
| 2:00—2:45 | 换为居民类别并重跑 | 由内核改变参与集合，而不是页面重算 |
| 2:45—3:45 | 报告修改与缺报 | 不同异常由不同层处理，缺报后说明覆盖 |
| 3:45—5:10 | 非法授权/回执 | 对象离开TLS连接后仍可核验，任务不能错用 |
| 5:10—6:00 | 不兼容组或证书 | 强制安全配置在真实连接上生效，不暗中退回 |
| 6:00—7:15 | 四组已实测对照 | 结果保持一致，A/B成本分别计量 |
| 7:15—8:00 | 导出与总结 | 原论文、我们新增什么、实验支持什么 |

若真实计算耗时长，提前生成可一次性使用的预计算并在说明中计入成本；现场等待阶段可以解释角色边界，不得加速伪造进度。备用用来自真实运行的回放，始终标明。

## 13.3 三分钟短版与专家自由提问

短版保留一次SAB正常任务、一个后量子对象错误、一项实际握手、结果对照和边界总结。使用既有真实记录展示耗时较长的四组实验，但不得称为刚刚实时完成。

自由提问时支持换一个未在主脚本中使用的合法类别，执行正常任务，再展示独立对照。不能只对固定40节点场景硬编码正确答案。

## 13.4 答辩必须准备的十个问题

1. 只是调用算法库吗？说明任务/令牌/回执的绑定、角色最小暴露、严格连接配置、错误路径与四组验证。
2. 论文已有内容与新增内容分别是什么？出示公式映射、变更表、代码路径和实验，不重复计算创新。
3. 有TLS为什么还签回执？连接保护与可保存对象验证是不同范围。
4. 是否整个PFDAM都抗量子？不是；A/B只增强指定环节，经典聚合与TLS身份认证边界单列。
5. 20%缺报后如何正确？对预期剩余有效集合正确，覆盖下降，没有补造读数。
6. 是否支持任意策略？不支持；有限复合标签与集合选择，且/或语义明确。
7. GW和UC串谋怎么办？超出原论文不串谋假设，不能用界面权限替代新的协议设计。
8. 如何知道页面不是模拟？对照实际run_id、签名对象、真实业务连接、独立验证器与导出复验。
9. 报告签名能证明计算无误吗？不能；完整性与统计正确性分别证明。
10. 社会价值是什么？减少不必要的明文暴露，保留群体统计用途，测量迁移成本；没有业务实证不报节能减排数字。

# 14｜验收测试：40项继承用例，加20项实现防错测试

`contracts/v3_acceptance_cases.json`原样保留T01—T40。Agent将每项转为真实可执行测试，不可为了测试总数好看重复断言或降低预期。测试定义和测试结果分开保存。

本手册配套`contracts/extra_acceptance_cases.json`增加E01—E20，覆盖先前设计中容易在实现时走偏的细节：全量报告后选择、独立集合真值、双签删除/算法混淆、实际库来源、业务证据关联、前端伪状态、离线复跑、假数据与真实密码区分等。

## 14.1 每项结果必须包括

case_id、构建提交、核心/参数版本、测试数据摘要、模式、实际命令、开始结束时间、退出码、断言结果、所需证据文件及摘要。状态用`PASS / FAIL / BLOCKED / NOT_RUN`；未运行与阻塞都不计入通过率。研究复核类用例另外保存安全结论，测试过程完成不意味着性质被证明安全。

负面测试要既看“是否拒绝”，也看拒绝发生在哪层；不能所有输入都拒绝然后声称攻击拦截率100%。每个功能保持相应合法通过对照。

## 14.2 集成与隔离测试

检查GW无明文fixture挂载、无UC私钥读权限、无法调用任意恢复接口；Source无法签发GW回执或UC授权；普通浏览器无法选择S0、调用故障注入、读取私有oracle。浏览器bundle、API、错误日志、导出、录屏都执行秘密扫描。

Source作为可信端可拥有明文；测试验证器也可拥有，但不得通过隐藏共享目录向GW传递答案。角色隔离是逻辑与进程级，不夸大为抵抗宿主机管理员。

## 14.3 故障恢复与并发

同报文超时重传、两个相同回执并发提交、封账后迟到、取消时任务仍在计算、服务重启后重放都必须有确定行为。SQLite唯一约束或等价事务机制保证幂等；不能只在内存set去重，重启后又重复发布。

预计算条目和快照的状态变更须原子化。崩溃后不确定是否使用过的预计算项宁可丢弃，不自动重新领取。复位清运行界面不重用密码随机量，不删除历史证据。

## 14.4 否决性缺陷

以下任一存在不得标记整件作品完成：REAL调用明文求和或占位密码；A/B只是独立探针；SAB可被客户端降级；签名/握手结果由场景开关伪造；GW读到全量明文和恢复秘密；oracle复用被测结果；没有合法成功对照；材料宣称已实测而证据为空。

# 15｜四组对照与性能研究

## 15.1 一个清楚的问题

在相同P1、数据、选择语义和输出目标下，分别加入A、B、A+B会改变哪些安全检查和实际成本？用实测回答，不预设“零开销”或后量子一定更快。

固定输入数据与语义任务，独立生成每次密码随机量和运行ID。比较恢复明文值与业务语义，不要求不同运行的令牌、密文或随机签名逐字节相等。

## 15.2 实验矩阵

主场景120节点、4窗口；确保不少于100节点的验收。扩展扫描可用100/300/600/900节点，策略数1/2/5/10/15。超过A/B与三类资源形成的6种词表时，显式扩展实验区域/合同词表，不用重复标签虚构l。

固定模数与群参数，记录参数维度变化。签名/验签微基准至少100次、首次握手至少30次、代表性端到端至少30次为目标；试跑不能替代正式样本，资源不足时明确减少样本及影响，不补造行。

运行顺序随机化或轮换S0/SA/SB/SAB，控制CPU负载、线程、热身与连接复用；记录失败而不只保留成功样本。主验收关闭会话恢复，复用实验与恢复实验分开。

## 15.3 计时与网络计量

记录初始化/参数、授权令牌、报告预计算、在线报告、匹配、聚合、原生验证、恢复、两类对象签验、L1/L2握手和业务端到端。使用单调时钟测持续时间，UTC只用于事件关联；跨进程时间不能简单相减得到可靠耗时。

端到端包含实际实现需要的IPC、序列化与调用开销。微基准可以单列纯密码成本。并行阶段可能重叠，不要求分阶段时间之和等于端到端。

握手按连接计，报告按消息或批次计；批量120报告只发生一次握手时，不能乘120。报告字节、签名字节、应用批次字节、TLS握手字节与网络抓包总字节分别命名。

## 15.4 图表清单

必须生成：四组结果一致性表；端到端耗时对比；两类签名的签/验耗时及对象大小；L1/L2握手耗时与字节；节点数扩展曲线；策略数量对网关耗时的影响。可增加缺报比例与有效覆盖图，但不能把覆盖下降当作隐私泄漏下降的实证。

每张图从原始结果脚本生成，附参数、单位、样本数、失败数和数据文件。展示中位数和适当分位数；样本不足不重点宣传p99。柱图不截断纵轴制造差异；不同量纲分图，不在同一根柱里混加毫秒和KB。

## 15.5 一项值得优先做的真实优化

完成正确基线后，优先评估有限批处理、连接复用、论文允许的单次预计算和实际库的多配对能力。每次只改一项，保留变更前后相同测试和参数。预计算不能复用秘密随机量，多配对实现必须经过等价验证，缓存不得跨任务/参数错用。

优化的价值是同目标下更低成本，不是用更弱参数、少处理一部分报告或删去验证来换取漂亮数字。

# 16｜证据包和离线复验

## 16.1 每次运行的内部记录

```text
artifacts/runs/<run_id>/
  run_manifest.json        results.json
  role_events/             connection_evidence.jsonl
  public_receipts/         performance_raw.jsonl
  tests/                   export_manifest.json
  private/                 # 访问受限，永不默认公开导出
```

私有目录可以包含测试报告映射、授权令牌与注入计划，但不保存无必要的长期秘密。密钥集中在角色的私有运行目录，不能混入证据包。

## 16.2 公开导出与专家复验包分开

普通导出包含作品/代码/参数/数据版本、获准发布的群体结果、签名回执、公开验签材料、实际连接元数据、性能记录与文件摘要。授权只公开摘要和签发元信息，不公开完整token_bundle或低熵标签。

授权验签需完整消息，公开摘要无法代替完整授权进行Pure ML-DSA验签。因此要明确：公开包可以复验回执；完整授权的独立验证在有权限的隔离专家包中进行。不能删除授权正文后仍声称公开包能够独立验证它。

专家包仅使用获准的合成数据与材料；包含独立oracle与复跑指令，但不把UC私钥或会话秘密作为公开材料。回执签名的有效性不独立证明明文统计一定对应密文；明文恢复由可信UC和隔离对照验证，说明这个信任边界。

## 16.3 防伪造证据原则

文件哈希检测传输变化，不自动证明测量者诚实。版本、命令、原始日志、实际调用路径和独立复跑共同支撑可信度。UI证据抽屉展示摘要与验证字段，按需打开实际文件；不能只截一张终端绿字。

不允许预先给JSON填`verified:true`、`actual_group`或性能数值。缺少某项证据时对应状态必须是UNKNOWN/PENDING，不能由配置推断为成功。
