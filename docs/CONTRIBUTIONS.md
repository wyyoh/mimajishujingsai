# 团队方案与系统实现

## 本轮发布保护与园区评估增量

本轮在团队PFDAM密态计算链之上增加UC发布控制：正式参与名册、固定分组、完整性检查、跨任务发布历史及原子提交共同决定公开范围；公开输入绑定采用按角色派生的HMAC标签，避免把可枚举读数的普通摘要公开作比对器。新V5任务/回执、UC结果V2、发布决定及评估声明将规则、上下文和签名结果关联，所有公开出口采用同一投影。固定分组精确发布只在所述受限查询与信任模型下约束披露，不宣称差分隐私或抵抗任意背景知识。

园区业务将三个参考日与一个事件日串成四个真实密态子任务，用16个窗口复算平均降负荷、相对变化、窗口能量差和完整覆盖。合成事件、三日基线误差、独立注入真值和最近一日对照分别记录；缺少任一必需分组时整套评估不发布。密码方案本身可以计算有效报告子集，业务层仍可因发布规则拒绝对外提供不完整群体统计，两者的职责不同。

同条件C0/C1实验保留相同密码运算、签名核验和计时边界，差异只在是否执行发布检查及历史事务。实验数值保留在隔离UC记录，普通业务没有关闭保护的开关；主配置及补充规模的代码、失败和原始样本分别追溯。研发记录见PRIVACY_SCENARIO_ITERATION.md。这些是应用工程、业务闭环和验证增量，HMAC、签名、SM4、TLS及标准库算法仍署名原来源，没有新增PFDAM数学证明。

## 团队前期方案

PFDAM为本团队自主研究方案，论文作者是团队成员；所提供13页论文用于解释方案，DOI 10.1109/JIOT.2024.3356593。细粒度标签授权、报告联合检查、盲因子消除、密态聚合、原生网关回执与限定域恢复属于我们的前期方案。本作品围绕该方案完成可运行密码应用系统。前期研究成果与本次实现迭代分列，避免将既有成果误写成本轮新增。

方案层的重点是让授权选择作用于真实密文集合，将配对等值测试与报告联合完整性检查衔接，再消除盲因子以恢复授权群体统计；单个节点缺报时，其余节点的报告仍可独立进入有效集合。当前系统验证了区域/类别复合标签、真实错窗/篡改拒绝和有效集合统计。策略/类别隐藏、实体不可链接及具体参数安全分别按复核结果限定，不把前期研究目标自动当作本次已证实性质。

参数参考 Ma、Han、Lei，Optimized Paillier’s Cryptosystem with Fast Encryption and Decryption，ACSAC 2021，DOI 10.1145/3485832.3485842。已核对会议主站摘要，完整构造未取得，参数安全审查保持待完成。摘要性能数字不作为本作品测量值。

P1 工程解释包括：标签到 GT、原生签名到 G1 的独立域哈希；非零求逆对象与临时量；拒绝报告 D0 单位元；固定最大度 15、合法零系数保留；普通整数恢复的显式上界。详见 CRYPTO_REVIEW.md，未宣称自动继承论文全部安全证明。
