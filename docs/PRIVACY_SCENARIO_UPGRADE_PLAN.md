## 3 发布保护的对象与信任边界

首版保护单位是预登记的独立计量点，不直接称为自然人数。多个计量点是否对应同一自然人或企业，需要实际业务登记关系；当前模拟身份不能证明物理主体唯一性。

UC 保存正式参与名册，使用私有、不透明的 contributor_id 关联同一计量点。参与名册必须含源归属、允许范围、版本和计量周期。换 Source、证书、任务 nonce、账户、场景名称或数据集别名不能自动生成新的隐私身份。

Source 生成专用的正式参与记录，将 report_id、contributor_id、时段和数据版本对应起来。首版在当前可信宿主模型下，通过角色私有 IPC 和可信协调进程向 UC 交付，检查来源进程、源身份及名册归属；不得读取或复用测试的 oracle_mapping.json。该机制暂不构成跨物理机构的独立名册认证，远程接入需另行设计认证交付。

GW 继续只接触现有报告 ID、密文和必要协议元数据，不获得源读数、UC 秘密、私有参与关联表或实验真值。新增关联表不得在 GW 目录、公共事件或公开包中出现。

UC 结合已核验回执中的 accepted_ids 和正式参与记录，核查每个有效报告对应哪个计量点。发现未知计量点、错源归属、一个时段同一计量点对应多份已接受报告或映射不完整时，首版拒绝整个窗口。不能只减计数而继续使用已经包含重复值的聚合密文。

上述核查仍依赖诚实 Source 与可信名册，不宣称解决恶意源伪造物理身份或读数的问题。

## 4 固定分组与发布历史

### 固定且不重叠的分组

先在 UC 私有名册上形成一组固定、不重叠的最小发布分组，每个计量点只属于一个分组。分组可以按获准的区域和资源范围事先形成，具体成员不提供给 GW 或普通查询者。

每个分组必须独立满足最小规模。查询只能选择这些完整分组或其并集，不能临时切出一个分组中的部分计量点。一个查询总人数足够，也不能绕过其中一个过小分组。任何并集还须满足原有主体权限，不自动扩大区域、资源类别或数据级别。

这会收紧临时细分查询，并降低缺报条件下的结果可用性。原有按区域、资源类别选择完整分组的能力继续保留；不以牺牲授权边界换取更大群体。

首版建议最小规模 k=10 个独立计量点；以 5、10、20 做敏感性观察。这些值是拟定实验参数，不是标准规定的安全线。

在固定成员、固定每时段输入、精确线性统计和受限查询模型下，已允许的输出只提供完整分组之和及其确定性派生信息，不新增分组内部的独立线性方程。这是本设计要验证的结构约束；辅助信息、已知其余成员读数、非负边界推断和恶意源行为仍可能造成披露。

### 为什么不只检查两次查询差集

多次线性查询的组合，可能在所有单次群体和两两差集都较大时恢复个体值。因此，两两差集检查只能作诊断，不能成为任意查询安全的充分条件。

首版通过固定分组约束查询表达，避免引入一个难以审查的通用重构检测引擎。验证中另外设置多方程重构反例，确认系统拒绝切开固定分组的查询。该数学反例是风险模型测试，不表示现有普通 API 已开放任意集合查询。

### 跨任务共享发布记录

UC 维护持久发布记录，隐私域由可信登记的数据族、计量点名册沿革及指标确定。身份别名和派生数据版本必须归入相同数据沿革，不能仅按 dataset_id 划分。

同一隐私域、分组和 UTC 计量区间，只允许一个对外数值版本。账户、函数、Source 数量、密钥轮换、任务 nonce、区域别名和新建数据集名称均不能清空该记录。不同账户可能共享已获结果，发布记录应跨潜在协作的查询者共用，不能只按单一用户名记账。

重复请求须重新检查访问权限。缓存引用显示 REPLAY 并保留原任务来源；需要 REAL 时继续执行真实运算和传输，核对结果与已发布版本一致，只新增任务关联，不新增披露。不能给旧签名换任务字段，也不能把缓存引用显示为新计算。

数据修订、分组调整或规则更新若与已发布分组交叠，不自动重新发布。首版冻结其数值修订入口，记录复核要求；如确需支持再发布，须先建立跨版本的联合披露分析。规则和密钥更新不得使保护条件静默降低。

## 5 缺报处理与全部出口控制

首版采用严格完整模式：各个参与计算的固定分组，在所需窗口内须由预登记的全部计量点提供一份有效报告，并满足 k。数据不足时保留内部计算状态，对外不给出精确数值。正常业务不能通过改用 COUNT、AVG 或新版本名称获取该窗口。

迟报可以在首次发布提交前补齐，补齐后重新核验输入及名册。首次发布以后，不因成员变化或数据补报自动改发另一结果。更宽松的降级覆盖率模式留待后续研究，本轮不同时实现。

必须覆盖的出口包括：任务结果、列表摘要、事件流、详情、UC 声明、回执附件、核验响应、图表数据、浏览器下载、服务端导出、重启恢复、旧版业务提交入口，以及实验入口可见的结果。旧格式离线验证继续保留；旧入口的新任务不能绕过新发布要求。

未发布对象不包含 value_W、精确均值、分子分母、差值、实际有效数和其他能还原隐藏结果的字段。也不包含待隐藏数值或可枚举参与集合的普通摘要，以免形成字典猜测入口。内部关联采用 UC 私有随机记录引用或受保护密文记录；公开决定可绑定随机化密文回执，但不声称它是公开正确性证明。

普通查询者只看到“未满足发布条件”等适度原因。精确缺报名单、内部数值和详细失败位置进入受控管理诊断；不得由普通事件日志泄露。角色原本可见的输入配置与实际观测计数要区别处理。

现有公开 UCI 数据的历史预览可保留“公开数据预览”标记，新增控制无法收回已经公开的信息。受保护私有数据不能借 PREVIEW 绕过发布检查。GRID_LAB=1 也不关闭正常 API 的控制；实验明文参考仅在隔离私有测试路径运行。

计算状态和发布状态分开。拟定发布流程为：待检查、预留、内部就绪、已发布、未满足发布条件；协议或证据错误另记拒绝状态。安全拒绝不显示为计算错误，密码失败也不能被包装成正常隐私抑制。

发布记录应采用跨进程互斥及持久事务。先预留并保存签名产物，再以事务提交对外可见状态；崩溃恢复必须确定哪些产物已经可见。两个同时到达的任务不能分别基于过期历史作出矛盾决定。

发布记录的最高状态与现有受保护根关联。旧备份恢复不得使已经发布的事实消失；缺少可信检查点、记录损坏或恢复状态不确定时停止数值发布。信任边界仍不抵抗连同受保护根一起回滚的宿主完全控制。

## 7 园区需求响应评估场景

场景要回答：在预先确定的事件窗口内，园区群体负荷相对参考水平变化了多少，数据是否足够支持比较，以及参与方能否核查计算依据。

采用一个母任务组织三个参考日和一个事件日。每个子任务保持现有最多四个连续 15 分钟时段，合计十六个窗口，无需把单个密态任务扩展到全天。UC 必须对全部窗口使用同一份预先冻结的计量点名册。

母任务绑定四个子任务的授权、数据族、固定分组、时段、源登记、算法套件和公式。全部子任务齐备且通过检查后，再提交整套对外评估结果；中途中断不发布半套比较。母任务在途期间纳入现有管理操作保护，避免密钥轮换与分步提交造成上下文混淆。

### 数据与事件安排

| 数据路径 | 安排 | 可以解释的结果 |
| --- | --- | --- |
| 固定种子的合成周数据 | 保留无干预轨迹，在事前固定的事件日对获准群体注入 0%、10%、20% 响应 | 受控模拟的已知注入量，以及参考基线带来的估计误差 |
| UCI 公开负荷 | 使用当前七天数据，保留公开读数与模拟分组来源，执行历史窗口对比 | 群体历史负荷相对参考水平的变化，不能认定真实需求响应效果 |

建议主场景使用合成周数据的第五个工作日，前三个最近完整工作日作为参考，事件为当地 17:00—18:00 的四个时段。UCI 对应 2013-06-07，参考 06-04、06-05、06-06；合成周对应 2026-10-16，参考 10-13、10-14、10-15。日期和群体在看结果前固定，不按效果大小挑选。

UCI 的时间标签、kW 单位和转换依据来自[数据集官方说明](https://archive.ics.uci.edu/dataset/321/electricityloadformatting)。已有导入记录将结束时间转换为实际区间并转成整数 W。参考日匹配使用当地时段，签名绑定实际 UTC 区间；合成数据的当前时区为 UTC。不能把两种时区的同一数组下标当作相同实际时刻。

不设置真实控制指令，不计算结算补贴或承诺经济收益。该场景对应资源聚合与需求响应评估方向，[国家发展改革委指导意见](https://www.ndrc.gov.cn/xxgk/zcfb/tz/202504/t20250411_1397162.html)提供业务需求背景，不规定本计划的三日基线或阈值。

### 业务指标与公式

令三个参考日同一时段的群体功率为 P1(t)、P2(t)、P3(t)，事件日为 Pe(t)，单位均为 W。

| 指标 | 计算规则 | 异常处理 |
| --- | --- | --- |
| 参考负荷 B(t) | 三个参考日同一时段功率之和除以 3 | 不进行事后调平，不使用事件日之后数据 |
| 时段负荷变化 D(t) | B(t) - Pe(t) | 保留负数，不把负荷增长截成零 |
| 平均降负荷 | 四个 D(t) 的平均值换算 kW | 负值按负荷增加说明 |
| 相对负荷变化 | 所有 D(t) 之和除以所有 B(t) 之和 | 分母为零时显示不适用，不显示无穷大或零变化 |
| 窗口能量差 | 所有 D(t) 之和乘 900 秒，再除以 3600000，得到 kWh | 仅表示一小时窗口的净变化，不直接称全天节能量 |
| 数据覆盖 | 每一窗口实际独立有效计量点数与冻结名册数比较 | 任一必要分组不完整，则本轮不发布精确评估 |

全部基础值以整数 W 处理，除法及派生指标使用精确有理数；只在展示时按事前指定规则舍入。不得把功率求和直接标为电量。

在受控模拟中，注入后的值按固定整数规则生成。独立实验真值分别保存“无干预事件轨迹”“注入后轨迹”和两者之差。业务估算 B(t)-Pe(t) 与注入真值的差，反映参考基线误差。0% 注入时估算变化不保证为零，10% 注入时估算变化不保证恰好为 10%。

设置事前固定的无事件窗口作安慰剂观察；若历史数据不足以形成不使用未来信息的参考日，标记无法评估，不伪造基线准确率。不得把一次受控注入当作真实市场因果效果。

## 8 同条件对照与实验设计

Material Passport：Origin Skill 为 academic-research-suite；Origin Mode 为 experiment planning；Version 为 privacy_scenario_plan_v1；Verification Status 为 UNVERIFIED。以下是计划与假设，不含新测量结果。

| --- | --- | --- |
| 正确性参考 | 相同节点、名册、窗口、缺报和注入数据 | UC/实验私有路径直接以整数和及有理数计算，不让 GW 读取明文；不作为同等安全的性能替代 |
| 业务干预对照 | 相同无干预轨迹、群体、事件窗口和三日参考方法 | 私有测试仅改变事前设定的 0/10/20% 注入，分别核对注入真值和业务估计误差 |
| 基线方法对照 | 相同群体、三个历史参考日、事件数据和注入真值 | 三日均值与最近单个参考日均从同一批输入派生；报告各自绝对估计误差，不按结果更换主方法 |
| C0 密态实验对照 | PFDAM、SAB、国密增强、密钥用途、三 Source、数据及场景相同 | 在隔离测试内部跳过发布判定与发布历史事务，数值仅进入私有测量记录；不产生面向用户的公开发布 |
| C1 启用发布保护 | 与 C0 一致，正常完成真实加密、签名和传输 | 实际执行固定分组、完整性、发布历史和事务检查，记录保护增量 |
| 风险机制对照 | 独立的风险查询模型及相同受控输入 | 比较仅最小群体、最小群体加两两差集、固定分组策略的拒绝边界；不扩大现有普通 API 的查询能力 |

C0 不是普通业务配置，不增加关闭保护的用户入口。两个密态组都保留双签和实际混合组，基础结果及同格式诊断声明的签名次数保持一致；C0 的诊断声明明确标为实验且未发布，不能充当正常发布决定。因保护产生的检查、持久化和投影处理才计为差异。正式业务不能以实验名义下调 SAB。随机量每次重新生成，配对实验复用的是数据和参数条件，不复用密码随机数。

业务估计误差按时段计算估计变化与注入真值之差，再报告绝对误差均值与最大值，单位为 W 或 kW。0% 注入时不以真值作相对误差分母。基线方法对照复用已完成的私有统计，不新增一轮密态输入或管理页面；一个固定事件上的结果不支持一般预测优越性。上述对照回答本轮业务可复算性、基线误差和保护开销，不宣称已证明 PFDAM 优于其他同态构造。

公开示范只发布事前冻结的单一响应情景，建议为 10% 受控注入。0%、20% 等对照仅在隔离测试中私有核验，不向同一业务发布域依次提供不同版本的事件读数。前端不得设置一个可以反复改写已发布事件的响应幅度滑块；新数据集名称不能将同一事件改装成新的隐私域。

建议主配置为 300 个逻辑计量点、三个同机 Source、三个参考日加一个事件日，每日四个时段。这里的 300 是输入总体规模，实际进入园区授权范围的计量点数必须单独报告。120 点及 900 点用于补充规模观察；900 点为合成数据。

主配置预登记 10 对正式样本；补充配置各 5 对。各配置另做两对预热并明确排除。每对的 C0/C1 顺序按事前保存的固定顺序随机化，交替执行以减少时序影响。风险测试、0/10/20% 注入正确性与性能测量分别编排，避免把所有维度做笛卡尔积。

每次保存代码与原生库版本、数据和名册摘要、规则版本、命令、依赖、配置、运行顺序、原始计时、CPU、RSS、链路字节、失败和超时。正式计时以母任务接纳后至评估对象可取得为界；单独列出排队、角色启动、数据准备、子任务、签名和发布事务耗时。两个实验组使用相同计时边界。

报告逐对耗时差、开销比例、中位数、最小最大值和失败数，不用这些小样本声称稳定 p95、统计显著提升或生产吞吐。主配置可先采用“十次中至少九次在 180 秒内完成”为建议工程目标，须在测量前冻结；它不是现有成绩、官方要求或安全阈值。若未达到则报告瓶颈，不能降低密码要求或删掉失败样本。

性能实验每次必须完整执行 REAL。重复数据触发发布复用时仍执行真实加密与核对；REPLAY 样本不能混入 REAL 性能统计。实验记录与业务运行目录、角色身份和发布记录隔离，不能用重置正常业务发布记录的方法获得新样本。

## 9 关键验证用例

| 用例组 | 必须观察到的结果 |
| --- | --- |
| k-1、k、k+1 与零值 | 小群体不发布，合法零值按正常值处理；满足条件时独立复算一致 |
| 多时段与跨源重复 | 一个计量点四个时段仍只算一个计量点；同一时段跨源重复报告拒绝整个窗口，不能只减计数 |
| 账户、函数、nonce、Source 与数据别名变化 | 不产生新的隐私身份或清空发布历史，SUM/AVG/COUNT 不能相互绕过 |
| 两次及多次组合查询 | 切开固定分组的请求被拒绝；完整分组并集在授权内可用；用多方程反例验证两两差集规则的局限 |
| 缺报、迟报和数据修订 | 必要窗口不完整则不发布评估；首次提交前可补齐；已发布后变更版本不能自动产生新数值 |
| 全部公开出口 | 被抑制的原始值、均值组成信息、可枚举摘要和私有名单不出现在 JSON、事件、文件、导出或恢复结果中 |
| 权限与规范字节 | 错账户、改规则、错任务、bool/整数混淆、错单位或错公式版本均被拒绝 |
| 并发、崩溃和恢复 | 发布事务结果唯一；签名中断和提交中断可确定恢复；旧备份不能抹去已经发布的历史 |
| 母子任务关联 | 调换参考日、混用不同群体、漏掉子任务、轮换中途状态或取消操作不会产生有效完整评估 |
| 业务公式 | 各子任务集合与整数和独立匹配；所有派生值精确复算；负变化、零分母、整数舍入和时区边界处理正确 |
| 响应注入与基线误差 | 无干预与 10/20% 注入真值分别核对；不把基线误差当密码错误，也不强行把零注入估值改为零 |
| 历史兼容与原有最低保护 | V1/V2/V3/V4 原归档仍可验证；新业务无旧入口绕过；GW 隔离、双签 AND、两段实际混合组均保持 |

独立预期集合和整数和仍由测试从输入与独立注入规则计算，不接受 GW 返回集合充当预期集合。正式参与名册、UC 发布判断、实验 oracle 是三类不同对象，应分别记录来源和使用权限。

对于每个事前登记的攻击用例报告原始轨迹、结果与泄露字段检查。可以写“登记用例均按预期拒绝”，不能转换成整体隐私安全率或形式化证明。

同时记录事前登记的合法请求中可发布的比例、因群体过小或缺报而不发布的比例，以及满足全部规则仍被错误拒绝的比例。前两项刻画策略可用性，最后一项检查实现错误；不把策略有意限制的请求混称为误拒。k=5/10/20 的私有敏感性观察同时报告这些指标，避免只展示攻击拒绝而忽略可用性代价。

## 10 前端与接口范围

继续使用现有八页结构。场景总览增加园区评估入口；协同任务页承载母任务进度、结果和条件说明；回执与审计页增加发布决定及评估声明。规模实验页增加对应成对记录，不创建通用隐私管理后台。

评估完成后突出平均降负荷、相对变化、窗口能量差和数据覆盖。曲线只展示已核验的四个事件时段参考值与事件值，不把源侧全天 PREVIEW 曲线画成全天密态评估结果。公式、数据来源、参考日和原始证据折叠展示。

界面区分“计算完成，等待发布检查”“结果已发布”“未满足发布条件”“证据核验失败”。未发布不显示数值零、空折线或可被下载恢复的隐藏值。计数采用“参与计量点”“有效报告数”两个名称。

新增接口围绕母任务创建、状态、经发布投影、发布决定核验和受控证据下载。命名与实现命令在 P0 阶段冻结；当前不新增可执行入口，也不修改服务配置。

## 12 本轮不扩展的范围及后续决策

本轮不调整 PFDAM 数学，不引入门限解密、零知识证明或正式差分隐私机制，不接真实调度控制和市场结算，不建设多租户管理平台。跨物理主机、真实电表与密码设备仍作为后续部署工作。

在实施前应冻结：最小计量点规模、分组方案、严格完整模式、母任务窗口、三日参考方法、注入规则、主实验配置和工程时效目标。默认建议已在本计划给出，修改须发生在相应实验开始前并保留版本。

本轮升级能够形成的贡献是：在受限查询模型下，将任务授权、参与名册、发布历史和签名结果关联；把同一条密态统计链用于可复算的园区负荷评估。它不会自动解决内核参数安全或已知候选识别问题。最终评价应分别审查核心方案、发布控制、业务估计和部署条件。
