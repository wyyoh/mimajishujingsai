## 1 作品功能与性能说明

作品围绕群体负荷统计建立本地可复跑的密态协同流程。Source 生成各逻辑节点的加密报告，GW 按 UC 签发的授权进行真实配对联合检查及密文聚合，UC 验证回执并恢复群体功率。任务授权和聚合回执采用 ECDSA P-256 与 Pure ML-DSA-65 的 ALL_REQUIRED 双签，两段角色业务链路均实际协商 TLS 1.3 X25519MLKEM768 并双向认证。

软件提供协同总览、聚合工作台、验证与报告三页，支持区域且类别选择、四个历史窗口、覆盖说明、六种真实受控情境、原始证据抽屉、公开导出和带来源的 REPLAY。默认数据 SYN-120-V3：A/B 区各60节点，各区24居民、20工商业、16充电。默认 A 区居民与充电共40目标，全部120报告由 Source 生成后上传，GW 决定有效集合。

PFDAM是本团队自主研究的细粒度密态聚合方案，论文作者为团队成员。论文用于说明我们的前期研究构造，本作品在该方案上完成任务化应用、双签与混合链路集成、角色隔离、故障恢复和可复验验证。前期方案与本次系统迭代分别说明，ML-DSA和TLS等标准算法及所用开源库正常注明来源。已验证低熵授权策略及多标签报告类别的候选识别限制，不宣称这两类隐藏性质。引用[37]全文经补查仍未取得，按用户授权使用官方摘要完成限定复核；具体参数安全仍待独立审查。

## 2 设计与实现方案

### 2.1 实现原理

四角色中 TA 负责可信初始化后退出常驻流程；Source、GW、UC 为独立 OS 进程。Web 控制器仅绑定本机8580，L1/L2 使用每次任务分配的回环端口。Source 不接收明文目标策略，GW 不加载源明文 fixture 或 UC 恢复秘密。角色在读取秘密前启用 Landlock，实际探测跨角色文件访问并记录拒绝。该隔离保护应用进程，不覆盖宿主管理员或掌控整个 OS 账号的攻击者。

PFDAM 标签包含 task_nonce、窗口ID、指标、区域和资源类别；任务/运行/参数及窗口起止由签名授权与报告/回执上下文检查绑定。UC 生成授权多项式及令牌；Source 对每份报告使用新的密码随机量。GW 通过配对结果计算联合检查用量，只有匹配授权且完整性成立的报告进入聚合，随后消除盲因子。UC 验证原生签名再在限定整数域恢复群体和。

P1 对原文歧义作显式工程解释：标签哈希进入 GT，原生签名哈希进入 G1，使用独立域；求逆秘密与临时量非零；拒绝报告 D0 为单位元，防止公开单位元 MAC 密钥退化；合法零系数令牌仍保留。普通整数恢复只在 2α×节点数×10^9 < N 的范围内使用，消息为非负整数 W，不静默替换为另一解密构造。模数3072位，子素数384位，BLS12-381，最大策略度15。论文 h 的声称阶与按公式产生的实际阶不同，生成器检查实际阶及恢复指数关系，不将这些功能检查当成参数安全证明。

任务对象使用 RFC8785 JCS 的受限输入域，拒绝重复键、非有限数、非法 Unicode、超安全整数和浮点；大整数为十进制字符串，二进制为规范 Base64url。签名覆盖对象类型、任务/运行/窗口/参数、安全配置、签发角色、接收方、有效期及令牌或聚合字段。ML-DSA 使用独立 context string，ECDSA 通过签名主体的严格object_type与对象模式区分用途。可信公钥从本地 role/key_id/epoch 注册表读取，不能由消息携带的新公钥替代；当前仅epoch=1，没有在线轮换/撤销。TLS与对象密钥分离，只读预检检查权限、密钥对应、指纹及证书计划有效期。

普通业务本地策略固定 SAB；消息自称 S0 不能降低 required 算法集合。签名数学有效后还检查任务与受理上下文。UC 以 run_id/slot_id 为唯一发布键，对相同 payload 重签视为幂等，对冲突快照或跨任务回执拒绝。签名有效、任务可受理、原生验证与恢复正确分别记录。

TLS 原生适配使用实际 OpenSSL SSL 对象完成传输和取证：只允许 TLS1.3、指定组、AES256-GCM-SHA384、证书链与角色主机名检查，关闭票据、会话恢复和0RTT。证据记录 actual_group、peer 身份、连接ID、进程实例、握手时延/BIO字节、业务请求引用。证书仍为 ECDSA；混合 KEM 不等于后量子身份认证，也不修复内层配对与 Paillier 的经典安全性质。

### 2.2 运行结果

正常全量任务四窗分别恢复183041、207672、204511、231233 W；每窗收到120、有效40，独立集合和数值断言均成立。20%目标缺报时收到112、纳入32、覆盖80%，只统计实际有效集合，不插补。修改报告情境在发送前改变一份目标 CT，联合检查拒绝该份；非法授权、非法回执和不合规 TLS 在对应层拒绝，不生成假结果。

### 2.3 技术指标

执行平台为 Windows + Ubuntu WSL x86_64，CPython3.14.4、OpenSSL3.5.5、mcl v3.08、glibc2.43、Linux6.18.33.2。前端 React/Vite 本地静态产物，没有 CDN、外部模型或远程 API 依赖。120 个逻辑节点由一个源进程模拟，两条业务连接每窗批量传输，不能把逻辑节点数写成部署设备数或握手数。

内核的消息范围、最大维度和恢复界限写入参数清单；每次运行包含代码/库摘要、数据摘要、param_id 与事件证据。正式主矩阵为四档各30次；数值、样本/失败数和图表由同版本原始记录生成，见 BENCHMARK_RESULTS.md。扩展扫描口径另列，不冒充主矩阵样本。

## 3 系统测试与结果

### 3.1 测试方案

保留原设计的 T01—T40，补充 E01—E20；测试定义与实际结果分开。合法正对照与负面输入共同执行，拒绝原因对应实际校验层。oracle 从私有合成 fixture、独立筛选条件和注入计划计算目标集合与整数和，不使用 GW 输出生成答案。参与集合与数值是两项独立断言。

### 3.2 功能测试

当前 pytest 执行44个测试，T01—T40/E01—E20的60项基础断言与R01—R06的6项恢复断言通过，没有跳过；这是实际实现覆盖，不能解释为对每一字段、档位、规模做了全部笛卡尔积证明。覆盖正常/缺报/零值/无数据、重复报告、类型域、候选策略限制、双签缺失或破坏、可信注册表、上下文、实际证书链/身份/过期、经典对端拒绝、TLS记录修改、文件访问和公开导出。

补充执行NIST官方固定提交的Pure ML-DSA-65 external sigVer组全部15例，3个合法和12个非法均符合预期，含0至255字节context；其他参数集及接口未执行。实际授权与回执的两算法各完成原生适配层和OpenSSL CLI双向验证，消息修改、错误角色公钥及ML-DSA错误context拒绝。命令、向量来源和摘要见crypto_conformance.json；二者共享OpenSSL实现，这不是独立实现互通或NIST算法/模块认证。

公开证据复核先保存旧验证器接受的五个改包反例，再修复结果与签名回执关联、窗口/快照唯一性、参数内容摘要及文件集合检查。重算摘要后的13类改包与5类包外错误预期任务均拒绝，未修改有效签名。整套回归另发现DrvFS替换快照时短暂缺失，现仅有限重试FileNotFound，不返回旧数据，也不重试非法JSON或签名错误；200次并发快照替换、永久缺失及非法JSON验证通过。

恢复测试真实提交并发回执、发送封账后改变的合法报告批、在首窗发布后取消计算、终止并重启API进程。异常退出后原任务明确终结，不自动续算；已发布快照重新核对回执签名并保留，原提交键仍关联原任务。损坏快照被拒绝。同一运行目录由文件锁限制为一个API实例，孤儿角色通过核对运行上下文的内核进程句柄终止；测试也用独立进程句柄确认其已退出。

新增普通 API 正对照完成真正120×4 SAB；客户端指定安全档位/密钥路径、重复 JSON 键、跨来源写入与实验入口被拒绝。同一 idempotency key 与相同参数返回同一运行，冲突参数拒绝。普通模式不公开实验 oracle 或实验记录事件。

### 3.3 性能测试

主矩阵固定同一参数实例与数据摘要，四档顺序打乱，每档30次；持续时间使用单调时钟，端到端包含角色启动、IPC、序列化、签验、完整 TLS 和 PFDAM，不含初始化与排队。证书认证保持相同，关闭连接恢复。L1/L2 每任务各一条完整连接，客户端视角各采30次；字节为 BIO 握手读写计数，非抓包总流量。

授权与回执各100次/算法的微基准保留实际 payload 大小、签/验耗时与签名字节，并包含密钥读取。节点扫描和策略扫描各3次，报告中位数与范围。主矩阵报告中位数与 p90；共享桌面和 WSL 未绑核，差异接近噪声时不宣传速度优势。

### 3.4 测试数据与复验

固定 seed 仅用于合成读数，安全随机量独立。干净复跑将源码、原生库及 wheels 复制到新目录，新建 venv 与密钥，在仅有 loopback、无外部路由的网络命名空间中完成真实 SAB 小流程、集合/值核对和文件隔离。验证范围是同一 WSL 主机上的新环境，尚未由第二台物理机复跑。

公开证据导出采用白名单，只包含群体结果、签名回执、公开参数、实际连接元数据、性能与摘要，排除令牌、私钥、单户明文和映射。归档校验器使用归档外独立信任的角色注册表，可指定预期run/task/param/profile/slot_count，核对结果窗口、计数及receipt_digest与签名回执一致。失败归档没有回执时不宣称认证成功。UC明文、覆盖率、预期人数、运行状态、性能和连接日志仍未签名，文件摘要可被重算，不能认证这些字段。回执签名不独立证明明文与密文对应；该关联依赖可信 UC 与隔离 oracle。复跑指令见 USER_GUIDE.md，原始结果见 evidence 目录。

加密和发布统计的隐私分别判断。小群体、单个有效报告或相邻查询差分仍存在披露风险，当前没有差分隐私预算或经论证的最小发布群体机制；不宣称已解决统计发布匿名性。完整恶意串谋模型、在线密钥轮换、HSM、SM2/SM3/SM4业务配置及第二台物理机复跑列为后续工作，不作已有能力展示。

## 4 应用前景

本作品可作为能源数据分域统计、保护对象迁移与失败路径教学的本地实验平台，展示在有限可信边界下减少网关明细暴露的实现过程。生产使用还需独立密码审计、参数依据、设备身份治理、密钥轮换、真实网络与资源评估、恶意源和串谋防护设计。当前没有接入实际电网或执行调度，也没有产品认证。

## 5 结论

作品已经建立可运行的选择性密态聚合、对象双签、两段实际混合 TLS、独立真值与可复验导出流程。新增贡献在任务一致性、角色分离、信任管理、失败关闭、幂等与迁移成本验证。限制明确保留：授权策略及特定条件下的报告类别可被候选识别，完整参数审查待完成，内层与证书身份仍为经典密码。功能通过与安全证明分别判断。
