# 演示与彩排脚本

录像建议使用 1366 或 1920 桌面。启动 `serve --lab`，确认页首 REAL、合成数据、参数审查提示均可见。讲解者手动按“下一幕”，可随时暂停。正式演示前运行 doctor、smoke 和 release-check；当前参数待审将使后者非零，这是明确的边界记录。

自由提问时暂停切幕，保留当前任务ID。需要切换缺报、非法授权、非法回执或不合规链路时，明确说明下一次真实运行的情境；计算超出时段时如实记录，不提前填写彩排通过。正常路径运行失败时按“现场恢复”处理。

## 现场恢复

正常任务失败时保留其 REAL 错误，打开证据定位，不替换成假成功。若现场无法继续计算，可明确选择历史记录进入 REPLAY，口头说明原始时间与 ID。不要把录播或原型当现场执行。重启 Web 不清除已完成证据；只在新空运行目录重新初始化密钥。

## 十个答辩问题与可出示证据

1. **只是调用算法库吗？** 底层复用OpenSSL和mcl；本次工作是PFDAM公式的有类型实现、任务上下文绑定、两个对象的联合双签、两段真实业务TLS、角色文件边界、独立真值与失败路径。出示CONTRIBUTIONS、源码路径和逐项执行记录，不将库算法计为原创。
2. **论文基础与新增内容如何区分？** PFDAM的授权多项式、报告、联合检查、密文聚合和原生签名属于本团队前期方案，论文用于解释这些构造；H1类型分离、恢复限定域等工程解释在CRYPTO_REVIEW登记。A/B集成、状态恢复、证据与迁移成本实验是本次工程工作；本轮工程修改没有新增内核安全证明。
3. **有TLS为什么还签回执？** TLS保护当前连接中的传输；对象签名覆盖可保存的规范授权与回执，断开连接后仍可用外部可信公钥验证。签名还绑定任务、参数、窗口和接收方上下文；有效旧签名不代表新任务可受理。
4. **是否整体抗量子？** 不作该结论。ML-DSA增强两个指定对象，混合组增强两段密钥交换；PFDAM的Paillier/配对和TLS证书身份仍为经典密码，内层参数审查尚未完成。打开保护范围说明及claims_registry逐项解释。
5. **20%缺报后怎样叫正确？** 默认40个目标缺8个，每窗收到112、纳入32、覆盖80%。独立oracle从应剩余的有效集合计算期望集合和值；恢复结果对该集合成立，未插补缺失读数。展示两个断言，而非只对GW自己声称的集合求和。
6. **支持任意策略吗？** 当前业务词表为A/B区域及居民、工商业、充电三类，区域与类别为且、多类别为或，完整复合标签按集合授权。策略扫描的15种标签是另列的实验区域/合同词表，不是假造15种业务资源，也不是任意布尔策略语言。
7. **GW与UC串谋怎么办？** 原研究保留TA可信、参与方诚实但好奇及GW/UC不串谋等假设。本作品不以界面权限替代协议安全；宿主管理员及控制同一OS账号也超出文件隔离保证。串谋防护需要另行协议设计和复核。
8. **如何证明页面不是模拟？** 创建新run_id，核对REAL事件、签名对象及两段同SSL对象的连接证据，再用隔离oracle和公开导出复验。REPLAY保留原ID/时间/档位。SYN表示读数是合成数据，密码运算和传输仍真实；错误情境实际修改对象或对端组。
9. **签名能证明统计计算正确吗？** 不能。外层回执签名验证对象来源与完整性，不能单独证明恢复明文与密文的对应关系；该关系依赖可信UC及隔离oracle。参与集合、数值、对象签名、连接身份/组分别判断，参数安全和隐藏主张也分别登记。
10. **社会价值如何表述？** 在限定信任边界下减少集中处理单户明细的需要，保留群体负荷统计用途，并提供迁移成本与失败行为的可复验实例。没有接入真实电网，不报告节能、减排、生产吞吐量或获奖数字；策略及特定条件下的报告类别可被候选识别也明确披露。

## 彩排记录

自动浏览器记录可证明页面操作、场景与状态，不能替代讲解者8分钟/3分钟带计时彩排。最终人工彩排需填写：日期、软件/参数/数据版本、正常与异常运行 ID、实际总时长、未完成环节、演示机器及讲解者确认，使用contracts/human_rehearsal_record.json空白表。当前未生成讲解者确认，不自动记为通过。

自动流程彩排由apps/web/scripts/record-rehearsal.mjs分别执行8与3分钟；记录真实操作耗时、任务ID、版本、导出摘要及浏览器错误，字幕和文件名明确说明无解说音轨。八分钟流程包含更换居民类别后重新运行、六情境、真实链路证据、已测对照与导出；三分钟流程保留正常SAB、非法回执、真实握手证据、结果对照与边界。实际执行结论以artifacts/tests/rehearsal_8min.json和rehearsal_3min.json为准。
