# 性能测量口径

## V4.1研发系列

V4.1由`scripts/v41_benchmarks.py`执行，每次新建带时间戳的实验目录，先保存plan.json及源码/原生库/脚本摘要。五种配置为Classic、SM应用、PQ密钥建立、Hybrid、Hybrid+SM；均使用相同的120逻辑节点、4窗口和独立集合/整数和核对。每配置预热1次不纳入分布，正式10次；每轮用固定排序种子41016打乱配置顺序，密码随机量仍独立生成。仅描述当前主机上的样本，不推导同等安全强度或微小差异显著性。

每轮额外在单独进程执行一次未保护的明文算术对照，并核对数据摘要、集合计数和四窗总和。明文计时仅包含进程内算术，排除数据生成与进程启动；密态计时包含角色启动、密码运算、序列化、两段真实TLS及恢复，排除fixture准备和排队。两者架构与安全能力不同，不能将两者耗时比当成同架构密码开销或真实电网吞吐提升。

CPU是各角色rusage的用户态/内核态CPU时间总和。内存是每50ms采样的存活角色RSS之和的峰值，共享页可能重复计算；不含API和浏览器。通信仅统计两条连接各一个客户端SSL BIO收发字节之和，含实际完整握手，不含TCP/IP包头。握手时间及握手字节也逐链路保留，不把两端视角重复相加。SM4位于TLS内，现有JSON应用帧编码的开销如实计入。

签名微基准采用同一实际回执payload，各测ECDSA、ML-DSA-65、SM2的签名/验签100次，包含应用密钥读取/解析和FFI；不把基准用途域签名当作新增业务签名对象。ML-KEM-768单独测100次EVP密钥生成、封装、解封装，核对共享秘密相同和修改密文产生不同的隐式拒绝秘密；不持久化秘密，也不将独立KEM成本代替TLS握手成本。这些接口均来自相同OpenSSL，不能称为独立实现认证。

四调用者线程实验由执行锁串行计算，保留调用者含排队时延。另启动隔离API，四个HTTP调用者同时提交不同任务，验证当前受理策略为1个接纳、3个409忙碌拒绝；被接纳任务独立核对结果。当前版本没有并行密态计算吞吐保证。

原始文件为plan.json、warmups.json、raw.json、plaintext.json、signatures.json、kem.json、concurrency.json、api_admission.json；summary.json只在系列全成功后更新最新指针。中位数和最近秩p90（排序后ceil(0.9n)-1位置）用于描述正式样本。失败、中断和源码变更记录保留，旧版本系列不改标为新源码成绩。浏览器从同一实测summary展示图表、CPU/内存/通信表并下载研发JSON，明确标记当前版本或历史版本。

## 历史730版本系列

主矩阵：S0（ECDSA、X25519）、SA（ECDSA+ML-DSA、X25519）、SB（ECDSA、混合组）、SAB（双签、混合组），相同 P1、参数实例、120 合成节点、4 窗口、默认 A 区居民/充电目标。每档30次，按固定数据种子生成相同输入；运行顺序用另一个固定排序种子打乱。每次独立生成密码随机量、任务/连接 ID，不复用秘密随机量。初始化不计入此端到端分布。

端到端从准备私有 fixture 且取得本项目执行锁之后、启动角色之前计时，到全部角色退出。包含进程启动、序列化、IPC、两段完整 TLS、对象签验、PFDAM、UC 验证恢复；不含 TA 初始化、数据 fixture 创建、排队时间或浏览器轮询等待。持续时间为单调 perf_counter_ns，UTC仅关联事件。各阶段可能跨角色重叠，不能求和当端到端。

主测量没有 CPU 绑核和实时系统隔离，使用共享 Windows/WSL 桌面；记录 CPU、内存、版本及每次 Linux loadavg。关闭项目自己的其他角色运行并用执行锁防止重叠。实验期间仅整理文档/脚本及读取资料；这仍不是实验室独占机器。接受系统噪声，不宣传小于噪声水平的微小差异。

每次运行 L1、L2 各一条连接，120 报告以每窗一批传输，不是120次握手。连接证据包含两端视角；统计握手时仅选客户端视角（L1 peer=gateway，L2 peer=utility），避免重复计数。handshake_ns 来自同一个 SSL 对象的本地 SSL_connect 区间；握手字节来自 SSL BIO 读/写计数之和，不包含 TCP/IP 包头、重传等抓包字节。握手时不含等待对端启动的排队区间。

签名微基准对主矩阵最后一次真实运行的授权与回执规范 payload 各采100次，分别测 ECDSA、ML-DSA 签/验。包括应用实际采用的密钥读取；不写为纯数学运算成本。载荷大小、签名字节均为真实编码测得。ECDSA DER 长度会波动，ML-DSA 不能与其他算法合并为一个对象大小。

扩展节点扫描100/300/600/900、各3次，只测1窗口 SAB；用于观察趋势，与主矩阵4窗口分开。策略扫描1/2/5/10/15、各3次，60份报告来自15个互异的 EXP 区域/合同标签，固定最大度15与同一参数实例，计时为进程内 GW 联合检查+聚合。合法零系数仍保留于编码，内核仅跳过单位元令牌系数；实际匹配成本与有效多项式维度相关。策略扫描不含 TLS/外层签名，也不伪称业务允许15种现有类别。

raw.json、signatures_raw.json、nodes_raw.json、policies_raw.json 分别保存原始样本；每行关联 run_id 或参数及输入语义。失败保留在文件，不补造或仅删失败。图表由 scripts/analyze_benchmarks.py 生成；主矩阵报告中位数与向上分位点 p90（0基索引 ceil((n−1)×0.9)），探索扫描只给中位数和样本范围，不宣传 p99。

该实验比较迁移成本和合成任务功能正确性。不能由时延、覆盖或签名通过率推导密码安全位数、隐私强度、真实电网吞吐量或获奖结果。
