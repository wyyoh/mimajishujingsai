# 作品展示设计

2026-10-18，用户决定暂停功能开发，转入作品包装。本轮处理当前八页工作台、项目首页和作品介绍，不增加业务接口、密码协议或性能测量，不制作提交压缩包或对外发布。

## 设计方向

面向密码应用技术评委，以电网数据在不同角色之间的处理路径为视觉中心。首页先说明业务价值，密码能力页说明团队贡献，任务与证据页承接实际操作。

主张：读数源侧加密，负荷按需汇总。PFDAM是团队自主方案；标准算法按实际应用用途介绍。

颜色沿用现有系统：画布白灰 #f5f8fa、表面白 #ffffff、主文字电网蓝 #153a52、交互蓝 #2365b0、发布绿 #157968、结构线灰 #d9e3e9。标题使用本机等线字体，正文使用微软雅黑，数字使用Bahnschrift；不引入远程字体。

布局左对齐，首页只保留一句价值主张、一句方案说明、场景选择与可点击的角色路径。密码能力使用一个连续的方案板，四项内容分别对应真实的计算、发布、签名与通信职责，避免算法名称堆砌。

```text
作品名称                           账户
场景总览                           模式 / 数据来源
读数源侧加密，负荷按需汇总          创建任务
居民负荷          园区响应          充电高峰
数据源   -> 密文 -> PFDAM网关 -> 统计端 -> 受控发布
统计方式                           密码能力入口
近期任务（按需展开）
```

第一版构思中的“大数字优势卡”和额外作品介绍导航均删除：静态规模数字会把历史实验误当作当前运行，额外入口会削弱已有任务主线。保留可操作的密文路径作为主要视觉记忆点。

## 文案原则

使用frontend-design组织信息层级，使用humanizer逐页审校。默认文案直接说明能力和下一步操作；研究问题和完整技术范围保存在原研发记录，精确的检查范围在相关详情中说明一次。保留实际错误、未发布状态、来源、受控模拟、同机条件、版本以及REAL/PREVIEW/REPLAY标识。

不增加首创、绝对安全、零泄露、整体抗量子、公开可验证解密、生产部署、完整标准符合性或奖项保证。统计签名表述为结果来源与内容核验；发布保护表述为固定分组、完整上报和共享历史约束。模拟10%响应描述为场景输入，不写成真实削峰收益。

## 验证范围

编辑前副本保存在artifacts/iterations/showcase/2026-10-18/before。执行TypeScript/Vite构建、实际Chrome八页检查、场景与导航检查、宽窄布局、既有任务回放及证据核验。仅回放已有授权任务，不为展示生成新业务结果。密码源码、原生库与既有实测文件逐字节保持。

文案与布局通过独立的新记录验证，不将旧界面截图重标，也不声称重跑全部密码回归。

首轮截图审阅发现四日期任务的32条链路端点记录占据密码能力页主体，已调整为先显示从实际记录计算的身份核对数量、密钥建立算法和业务保护，再按需展开完整表。全部端点原记录与核验结果保留，避免用长表淹没方案贡献。
