# 使用指南

当前新增V5发布保护与园区评估。默认工作台选择“园区多主体协同”，进入“协同任务”运行评估：三个参考日、一个事件日，各四个15分钟窗口，全部通过发布检查后展示四项指标和两条四点曲线。300个输入计量点的合成A区评估实际参与150点；输入规模与授权参与数须分别看待。合成事件固定10%注入，UCI公开负荷只作历史比较，不能调整响应幅度反复公开同一事件的新读数。

近期列表来自当前运行环境的API提交索引，随后逐条检查账户和运行权限；直接执行的私有实验不进入普通列表。历史证据仍可按各自原始记录离线核验。

普通聚合和园区评估均执行固定分组、至少10个独立登记计量点、完整上报和共享发布历史。未满足规则时显示未发布，不把缺少数值显示为零。“回执与审计”可核验发布决定；已发布的评估可复算签名输入及业务公式。取消或拒绝而未形成发布决定时不提供完整证据下载。签名不单独证明解密正确或读数真实；固定分组精确发布不是差分隐私。

“规模实验”读取预登记的C0/C1串行成对测量，两组都完成真实密码计算；C0只在隔离测试内跳过发布判定，普通页面不能关闭保护。数值对照保留在UC私有记录，页面提供耗时摘要、版本、样本范围及下载。不同版本的规模记录不作为同一构建的扩展性结论。`?v41=1`和`?legacy=1`仅保留历史研究页面，旧创建接口返回关闭说明；原归档可离线验证。下文V4.1操作及交付说明属于历史版本。

2026-10-17标准对齐研发迭代已加入软件秘密托管、管理审批审计、对象签名/TLS身份更新撤销、受保护备份及V4统计端结果声明。具体身份、秘密保管和故障恢复见[管理操作](STANDARDS_OPERATIONS.md)，算法用途与版本见[清单](CRYPTO_INVENTORY.json)。本页旧版本实验与交付说明保留原归属，最终材料和新发布包继续暂停。V4可认证UC结果声明来源与内容；它仍不构成解密正确、源全集完整或统计发布隐私证明。

## 支持环境与入口

软件版本 0.1.0；PFDAM 工程解释 P1-functional-typed-v1。已验证环境是 Windows 上的 Ubuntu WSL x86_64，Linux 6.18.33.2、glibc 2.43、CPython 3.14.4、OpenSSL 3.5.5、mcl v3.08。角色隔离需要 Landlock ABI≥3。发布包的离线依赖是 CPython 3.14 Linux x86_64 wheels；不承诺 Windows 原生、旧 Ubuntu 或 ARM 兼容。

首次源码构建需要已有 WSL、G++、GMP 开发库、OpenSSL≥3.5.5 开发库、Python venv 和 Windows Node.js。运行 `scripts/project.ps1 build` 生成原生库、Python 环境及前端。构建只使用项目目录，不替换系统密码库。离线交付包中已含原生库、静态界面与 wheels；在兼容 WSL 中运行 `bash software/scripts/install_offline.sh`，安装器先校验文件摘要，再创建环境和新密钥。

Windows后台启动：`scripts/project.ps1 start`。新版默认入口为 http://127.0.0.1:8580/ ，也保留 http://127.0.0.1:8580/?v42=1 ；V4.1研究工作台入口为 http://127.0.0.1:8580/?v41=1 。绑定回环地址，面向本机演示。需要本机原型账户登录；运行`项目根目录\scripts\project.ps1 access`查看本机访问口令，私密口令不得分享或打包。A/B运营方分别限定对应区域，分析方仅能访问一般级模拟资产。`start --lab`显式启用公开UCI预览和受控故障，V5不公开Source私有对照。普通业务入口不能指定实验档位或注入故障。

`scripts/project.ps1 status`查看后台状态；`scripts/project.ps1 stop`正常停止。重复`start`返回已有实例，切换`--lab`需先`stop`，不自动改模式或降低保护。停止会取消尚未完成的任务。状态管理只停止由该启动器记录且进程身份核对通过的本项目服务，不停止占用同一端口的其他进程。日志在仓库外私有运行目录的`server.log`，状态命令显示其路径。

后台启动器由隐藏的Windows WSL进程持续承载前台API，启动命令结束后仍可访问。只启动Linux systemd后台服务不足以维持WSL运行。电脑或WSL重启后需再次运行`start`；服务重启后重新登录。Windows及Linux的前台命令仍为`serve`或`serve --lab`，使用时保持终端打开。后台`start`功能由Windows PowerShell启动器提供，密码计算仍在Ubuntu WSL中执行。

浏览器出现`ERR_CONNECTION_REFUSED`时，先运行`status`。`STOPPED`表示没有后台服务，可运行`start`或研发用`start --lab`恢复；`PORT_IN_USE`表示端口由未纳入本启动器管理的进程占用，不会擅自停止该进程。运行成功后刷新页面即可。

## V4.1页面操作

首次运行任务会弹出登录窗口；旧工作台也提供“登录账户”入口。项目根目录运行`.\scripts\project.ps1 access`查看对应账户口令。登录有效期为30分钟，服务重启也会使登录失效；页面收到401后会提示重新登录，并保留所选任务条件。登录成功后再次点击运行或原操作，不会自动重复提交任务。更新前已打开的页面请用Ctrl+F5刷新，以加载新的登录引导。

运行总览显示实际可见记录和当前任务证据，数据资产展示三类模拟标签，授权策略检查账户、数据范围、统计方式、密码方案和有效期。模拟规则分不是正式定级；重要数据模拟场景必须使用Hybrid+SM增强。PREVIEW只检查规则，不产生签名授权。

密态聚合可选SUM、AVG、COUNT，默认A区居民与充电共40个目标；120个合成逻辑节点照常生成密文报告。点击“运行协同任务”重新决策并签署V2授权，完成两段实际混合TLS、PFDAM联合检查、UC恢复与签名关联核对。AVG按总和/有效报告数给出精确分数；COUNT来自签名回执计数。只有显式实验环境可查看隔离Source合成对照，GW不加载明文。

密码能力分别显示对象签名、实际组、经典证书身份和TLS内SM4业务保护；SM应用模式不是TLCP。研发实验记录按版本提供图表与JSON导出，实验配置不进入普通业务降级入口。回执验证逐项核对签名、策略、密文快照/包含证明、集合与聚合密文摘要、审计检查点；不认证UC明文或证明源集合完整。

安全审计分别呈现GW签名锚定检查点与普通进程事件。安全自检调用真实原生探针、证书余量检查和当前运行证据，PENDING/PARTIAL不会显示成全部通过，也不替代正式密评。实验JSON和原型自检JSON是软件功能输出，不是最终提交材料。

改变任务条件清空旧指标。选择历史记录进入REPLAY并回显原始策略；不重新执行密码。真实失败保留REAL、拒绝原因和已发布快照，不自动回退。旧研究工作台由`?legacy=1`进入，旧任务创建入口同样执行登录与授权，V1归档仍可验证。

同一运行目录只允许一个API实例。正常停服请求取消未完成任务；异常重启后终止本任务的孤儿角色，重新核对持久化回执与V2快照/审计关联，标记FAILED／SERVER_RESTARTED，保留验证通过的快照，不自动续算。相同提交键返回原任务；新的键重复使用nonce会拒绝。恢复数据损坏时保留私有原件，不发布失效快照。
## 六种受控情境

| 情境 | 实际注入与预期表现 |
|---|---|
| 正常统计 | 120 份报告/窗；默认纳入 40；集合、数值一致 |
| 修改报告 | 生成后、TLS 发送前改一个目标 CT；联合检查拒绝该报告 |
| 20%目标缺报 | 每窗阻止 40 个目标中的 8 个；收到 112、纳入 32、覆盖 80%；不插补 |
| 非法授权 | 改已签对象字段；GW 验签失败，不开始报告聚合 |
| 非法回执 | 改已签回执；UC 拒绝发布 |
| 不合规链路 | 对端仅允许经典组；SAB 握手失败，没有回退 |

“下一幕”仅选择下一情境，“返回正常”复位选择，“查看证据”打开当前任务证据。讲解者手动控制运行，不靠固定动画假装处理。

V4.1实验入口另提供快照根、授权策略、聚合密文摘要和审计事件的角色链路故障；可信回执页提供11类证据副本修改，包括快照记录/根、策略、聚合摘要、审计修改/删除/重排、参与集合、签名、密钥版本类型及错误预期上下文。副本攻击重算普通文件摘要并保留原签名，拒绝后再次核对原本和正确副本；原运行不被修改。越权、nonce重放、跨主体读取和SM4帧重放另由真实接口或协议测试验证，不把它们伪装成同一种归档攻击。

## 命令

以下命令前缀在 Windows 为 `scripts/project.ps1`，在 WSL 项目根目录为 `bash scripts/project`。

| 命令 | 作用 |
|---|---|
| `start [--lab]` | Windows后台启动；退出启动终端后继续运行，同模式重复启动复用实例 |
| `status` | 查看由后台启动器管理的服务状态、访问地址和私有日志路径 |
| `stop` | 核对进程身份后正常停止后台服务，取消未完成任务 |
| `serve [--lab]` | 前台运行，需要保持终端打开；Linux/WSL亦可用 |
| `doctor` | 收集版本、库来源、CPU、内存；不上传 |
| `access` | 本机查看原型账户口令，内容私密，禁止公开或打包 |
| `init --profile SAB` | 初始化本地密钥、角色证书和参数；已有材料不覆盖 |
| `smoke --real --nodes 12 --slots 2` | 真实小流程，含独立 oracle |
| `demo --profile SAB --dataset SYN-120-V3` | 120 节点四窗口正常演示 |
| `test --suite acceptance` | 在私有隔离运行目录执行pytest，保持当前研发API可用；记录命令、版本和逐项结果 |
| `ui-test` | 启动临时实验服务（若端口未用）并用 Windows Chrome 验收 |
| `offline-test` | 新目录/环境/密钥、无外部网络路由，真实复跑 |
| `bench --profiles S0,SA,SB,SAB --repeats 30` | 四组正式实验；已有原始结果时拒绝覆盖 |
| `export --run ID --public` | 输出白名单公开证据 ZIP |
| `verify-export --path PATH` | 校验摘要及回执所需签名，使用外部可信注册表 |
| `verify-export --path PATH --expect-run ID --expect-profile SAB --expect-slots 4` | 从归档外约束预期任务；核对签名关联，不认证UC明文/日志 |
| `release-check` | 检查门槛；参数安全待审时非零退出 |

Python 依赖在 requirements.lock.txt，前端在 apps/web/package-lock.json。报告、录像生成是独立的开发工具，不是运行依赖。完整测试含真实停启与故障恢复，可能需要约两分钟；120×4 单次运行在本开发机约十余秒，正式结论以原始统计为准。

V4.1正式研发系列在WSL项目根目录运行`.venv/bin/python scripts/v41_benchmarks.py --repeats 10 --nodes 120 --slots 4 --micro-repeats 100`。测量时避免额外提交业务任务；每次创建新的带时间戳目录，包含五套件、明文对照、签名/KEM、排队和HTTP受理原始记录。口径见BENCHMARK_METHOD.md；密码中心读取最新成功系列，源码不一致时标记历史版本。下载的是研发实验JSON，最终提交材料仍暂停。

逐项验收记录区分实时调用断言与既有执行证据复核，包含实际命令、开始／结束时间、退出码、源码与测试工具链摘要、参数及输入来源、引用文件摘要。没有Git提交时明确记录null，使用文件摘要标识本地源码。运行`.venv/bin/python scripts/verify_acceptance_provenance.py`检查工作目录证据；对交付包使用`software/.venv/bin/python software/scripts/verify_acceptance_provenance.py --package-root <解压根目录>`。公开包会单独列出原始摘要与匿名副本摘要，文件摘要不替代来源认证或正确性证明。

## 数据与密钥

测量数据使用固定 seed=20261015 的合成整数 W，密码随机量来自安全随机源，与数据 seed 独立。每次新任务、报告、临时量重新生成。没有可复用秘密预计算缓存。

秘密默认放在 WSL 用户目录 `~/.local/share/grid-collaboration/<workspace-hash>/`，位于源码树外。TA、Source、GW、UC 文件分开；角色进程启用 Landlock 后只读自身秘密与获准公开文件。宿主管理员与控制整个同一 OS 账号者不在该隔离保证范围内。

证书有效期较短（CA30天，角色14天）。现在可通过独立批准的`renew-tls`更新角色证书，仍受当前CA有效期约束；到期身份不通过业务鉴别。CA根、PFDAM参数或独立托管根迁移尚未自动实现，每个运行目录仍只对应一个参数实例。这类迁移采用新的可信环境并保留原始参数和公开历史信任资料，不能直接覆盖含历史记录的目录或关闭证书验证。GRID_RUNTIME及独立托管根位于源码树外，含秘密，不进入公开证据。

检查密钥时用`.venv/bin/python scripts/key_readiness.py --output artifacts/iterations/standards/<新的记录名>.json`核对私公钥对应、指纹及证书剩余时间，默认余量7天；可加`--planned-at`核对未来开发时段。初始证书不能自动覆盖11月，应以实际检查结果安排更新或CA迁移。对象签名密钥现支持登记式多epoch轮换/撤销；主环境为兼容旧入口保留epoch1，隔离验证环境已实际完成epoch1→2→3。人工建立新参数环境仍不同于原环境的密钥更新。

`.venv/bin/python scripts/crypto_conformance.py`执行随包固定的NIST选定15例向量及真实对象CLI/适配层交叉验证；`.venv/bin/python scripts/export_audit.py`执行18例改包及错误预期上下文拒绝。两者会产生新实际记录和运行，保留原交付 evidence 供对照。归档验证输出明确列出未签名字段：V1/V2/V3的UC明文未独立签名，V4由UC结果声明认证来源和内容；所有版本均不独立证明解密正确、源全集完整或统计发布隐私，性能和连接日志也未因此认证。

## 排障

`TLS_HANDSHAKE_FAILED`：检查两端组策略、证书有效期/身份及 OpenSSL 实际库。`OBJECT_SIGNATURE_INVALID`：查看失败对象和 required 签名，不改为 OR 规则。`AUTH_EXPIRED`：签名可能有效，但业务时效不成立。`RUN_IN_PROGRESS`：等待或取消现有任务；正式测量持有执行锁时，新任务会排队。

`Landlock unavailable`：使用支持 ABI≥3 的 Linux 内核。`Existing raw benchmark records`：原始证据受保护，需要新系列时使用另一个目录，不删除或覆盖原记录。浏览器验收要求 Windows Chrome 与 node.exe；可设置 PLAYWRIGHT_EXECUTABLE 指定已安装的 Chromium。

当前内层参数审查标记 PENDING_REFERENCE_37_REVIEW 属于已知研究限制，不能通过编辑标记获得安全认证。详见 CRYPTO_REVIEW.md。

用户已授权在合法全文补查无果后采用引用37官方摘要作限定复核，见REFERENCE37_REVIEW.md；该回退不等于具体参数已获安全认证。已有报告、PPT和录像均为过程稿；按用户指示暂停最终材料、录制彩排与发布打包。V4.1研发记录见V41_ITERATION.md，密码设计见V41_SECURITY_DESIGN.md。
