# 场景总览精简迭代

2026-10-17，根据用户“字不要太多，页面高级且直观”的要求，按frontend-design重新组织总览，并以humanizer审校新增短文案。操作、数据和密码规则沿用原实现。

总览现在由一块流程板承担主要展示：顶部选择三个业务场景，中间显示数据源汇聚到PFDAM网关、再由统计端核验的路径，下方切换总和、平均值和报告数。流程节点可以进入相应页面，创建任务与查看数据的入口并列。近期任务默认收起，展开后仍可查看、回放和扩展近期记录。

浅灰底、深蓝主文字和细线保持原界面风格；PFDAM节点是视觉中心。移除了总览的两段说明、独立指标带与场景长文，必要文字保留在数据、密码和核验页面。相同匿名默认状态下，main区域可见中文字符从548降至200，约减少63.5%；该计数不含侧栏与顶部品牌，也不等于整个应用的字数。

流程明确标为示意。数据来源、模拟分组、同机进程及PREVIEW/REAL/REPLAY仍然可见，没有增加伪实时动画或虚构统计值。场景和统计方式只更新已有任务条件，不自动提交任务。原PFDAM数学、SAB双签名和混合通信、服务端权限与签名协议保持原字节。

类型检查、生产构建及四组Chrome检查通过：总览布局与交互、三源真实任务和回执核验、V4.1研究入口及基础聚合入口。布局检查覆盖320、390、768、1024、1366、1440和1920像素宽度的选定视口；人工复核了桌面单源/三源图与手机图。另有两项既有浏览器证据回归核对当前前端摘要、核心版本及运行引用。没有重跑完整密码回归或产生新的性能系列。

运行验证时按顺序执行下列脚本，避免同时提交任务触发单任务受理限制：

```text

node apps/web/scripts/v42-ui-check.mjs
node apps/web/scripts/v41-ui-check.mjs
node apps/web/scripts/ui-check.mjs
```

本轮记录在artifacts/iterations/overview-refinement，完成索引为completion.json。原代码、已修改的追溯脚本和研发文档副本保存在.build/overview-refinement/before；此前frontend-refresh目录及其完成索引保持原字节，旧测量仍属于原时点。最终提交材料、录制、打包和远程发布继续暂停。
