# 《面向新型电网的细粒度密态聚合与可信数据协同平台》
## 夺冠级 V4.1 最终方案与增强实施设计

> **文档用途**：全国密码技术竞赛复赛作品开发、作品报告、演示系统、答辩材料的统一技术基线。  
> **正式参赛名称**：面向新型电网的细粒度密态聚合与可信数据协同平台  
> **核心定位**：面向能源可信数据协同场景的密码增强型数据安全基础能力验证平台。  
> **设计原则**：不追求功能数量，而追求“业务问题—密码机制—工程实现—验证证据”完整闭环。

---

# 1. 项目最终定位

本作品不应被设计成一个单纯的“电力数据加密平台”，也不应做成大而全的能源数字化平台。

最终定位为：

> **面向新型电网及能源可信数据协同场景，提供数据分类分级、细粒度授权、密态聚合、国密/后量子密码敏捷通信、可信回执与可验证审计的一体化密码应用平台。**

核心要解决的问题是：

> 在多个能源数据主体需要开展联合统计、分析和协同时，如何做到“数据可用但明文不可见、权限可控、通信可信、结果可验证、过程可审计，并能够向后量子密码体系平滑迁移”。

整个系统围绕这一条主线展开。

---

最终系统形成：

```text

      │
      ▼

      ▼

      │
      ▼

      │

 ML-DSA / SM2     安全通信
      │          SM / PQ / Hybrid
      │              │
      └──────┬───────┘
             ▼

             │
             ▼

             │

```

因此作品不是多个独立功能的拼接，而是一个完整的：

> **可信能源数据协同密码闭环。**

---

# 3. 为什么这个方向符合当前产业趋势

## 3.1 能源数据安全已经成为现实产业问题

当前能源行业数字化不断深化，数据处理已经覆盖收集、存储、使用、加工、传输、提供、公开、删除等全生命周期。

因此能源数据安全的重点已经从：

> “数据库加密”

逐渐转向：

> “数据全生命周期安全 + 跨主体可信协同”。

本作品重点解决的正是后者。

---

## 3.2 与能源可信数据空间方向高度契合

可信数据空间的核心并不是简单的数据交换，而是：

- 数据资源共享；
- 数据使用控制；
- 跨主体可信协同；
- 数据流通安全；
- 履约行为存证；
- 全程溯源；
- 隐私保护与密态计算。

本作品的：

- 细粒度授权；
- PFDAM密态聚合；
- Snapshot；
- Receipt；
- Merkle；
- 审计；

可以自然嵌入能源可信数据空间体系。

因此产品的产业故事应该从：

> “我们做了一个电力密态计算Demo”

升级为：

> **“我们为能源可信数据空间提供密码增强的数据协同基础能力。”**

## 4.5 国密体系

外围密码能力采用：

- SM2：身份认证、数字签名；
- SM3：摘要、完整性、证据绑定；
- SM4：需要对称加密的场景；
- TLCP / 国密通信机制：根据实际工程实现选择。

注意：

> PFDAM密态计算内核作为研究型密码机制保留，不强行替换成国密算法。

正确表达是：

> **国密密码机制负责外围身份、完整性和通信安全，PFDAM负责密态数据计算。**

# 5. 后量子能力必须同时做 A + B

最终方案确认：

## A. 后量子任务授权与聚合回执

采用：

> **ML-DSA**

解决：

- 谁发起了任务；
- 谁批准了任务；
- 授权策略是否被修改；
- 聚合结果是否由可信节点产生；
- 回执是否被篡改。

任务授权签名建议绑定：

```text
task_id
requester_id
data_scope
aggregation_function
time_window
policy_digest
snapshot_root
algorithm_profile
timestamp
```

签名：

```text
ML-DSA.Sign(...)
```

验证：

```text
ML-DSA.Verify(...)
```

这样后量子密码不是“算法展示”，而是进入业务核心流程。

---

# 6. B. 后量子通信增强

通信层采用：

> **经典算法 + 后量子算法的混合密钥建立**

优先围绕 TLS 1.3 / Hybrid PQ 机制实现。

核心目标：

```text
客户端
  │
  │  Hybrid Key Exchange
  ▼
可信数据协同网关
  │
  │
  ▼
聚合服务
```

建议重点展示：

- Classic；
- SM / 国密模式；
- PQ；
- Hybrid。

并测量：

- 握手耗时；
- 密钥建立耗时；
- CPU开销；
- 网络报文开销；
- 并发能力；
- 任务端到端耗时。

注意：

> 后量子通信解决“密钥建立”，ML-DSA解决“授权与签名”，两者职责必须清晰。

---

# 7. 密码敏捷架构：把多种算法变成一个创新点

不要做：

> “系统里面有很多算法按钮”。

而要设计：

# Crypto Agility Layer

统一接口：

```text
CryptoProvider
 ├── ClassicalProvider
 ├── SMProvider
 ├── PQProvider
 └── HybridProvider
```

上层业务不直接依赖具体算法。

例如：

```text
AuthorizationService
        ↓
SignatureProvider
        ↓
SM2 / ML-DSA
```

通信：

```text
SecureChannel
        ↓
KeyExchangeProvider
        ↓
Classic / SM / PQ / Hybrid
```

最终形成：

> **密码算法可替换、可迁移、可配置，而不需要修改业务逻辑。**

这比简单增加ML-DSA更有工程创新性。

# 8. 数据分类分级模块

这是V4.1新增的重要治理能力。

## 8.1 基本流程

```text
数据进入
   ↓
识别数据类型
   ↓
识别业务敏感属性
   ↓
风险评分
   ↓
安全等级
   ↓
生成保护策略
```

可以设置：

- 一般；
- 敏感业务数据；
- 重要数据模拟标签。

必须在系统中注明：

> **演示系统中的等级属于模拟分类标签，不代表对真实能源数据进行正式定级结论。**

---

## 8.2 分类结果驱动密码策略

例如：

```text
一般数据
 → 标准保护

敏感数据
 → 加密 + 授权 + 审计

高敏感/重要数据模拟场景
 → 密态计算
 → 强授权
 → PQ/Hybrid通信
 → 签名回执
 → 完整审计
```

这样分类分级不是一个“展示页面”，而是能够真正驱动后续密码机制。

```text

    ↓

    ↓

    ↓

    ↓

```

展示页面至少同时呈现：

### 左侧

明文数据：

```text
用户A = ...
用户B = ...
用户C = ...
```

### 中间

密文：

```text
Ciphertext

0x...
0x...
```

### 右侧

聚合结果：

```text
SUM = ...
AVG = ...
COUNT = ...
```

并强调：

> 协同计算过程中，聚合节点无法直接获得用户级明文。

# 11. 可信数据快照

不引入区块链。

采用：

> **Hash + Merkle Tree**

形成数据快照。

每次任务记录：

```text

Dataset Version
Record Count
Merkle Root
Timestamp
Policy Digest
```

作用：

> 证明“本次任务到底使用了哪批数据”。

# 19. 不再加入的功能

以下功能正式从核心方案删除：

## ❌ 区块链

理由：

- 与核心密码问题联系不够紧；
- 增加工程复杂度；
- Hash/Merkle已经可以满足当前证据需求。

## ❌ ZKP

理由：

- 引入新的密码学证明体系；
- 开发和解释成本高；
- 与PFDAM主线没有足够强的必要联系。

## ❌ 大模型助手

不作为核心功能。

原因：

> 作品已经有足够明确的密码创新，不需要为了“AI”而AI。

如果后期有余力，只允许作为辅助工具，不进入核心答辩主线。

## ❌ 3D数字孪生

删除。

展示效果可能很好，但不能提高核心密码技术评分。

## ❌ 电网调度预测

删除。

这会使作品从密码竞赛偏向能源AI竞赛。

# 30. 结论

最终版本不再继续扩展“看起来先进”的功能。

作品应该围绕：

> **能源数据可信协同**

建立一条完整的密码技术链：

**分类分级 → 动态授权 → PFDAM密态聚合 → 国密/PQC通信 → 可信回执 → Snapshot/Merkle → 审计与安全自检。**

其中：

- **PFDAM**负责解决“能不能在看不到明文的情况下计算”；
- **动态授权**负责解决“谁能做什么”；
- **SM2/SM3/SM4**负责现有国密体系适配；
- **ML-DSA**负责后量子授权与回执可信；
- **ML-KEM/Hybrid TLS**负责后量子通信迁移；
- **Snapshot/Merkle**负责数据与结果证据；
- **安全自检**负责将系统实现映射到密码应用安全要求。

最终目标不是做一个最大的系统，而是做一个：

> **技术主线高度集中、密码机制真正落地、标准依据清晰、产业场景真实、攻击验证完整、展示效果惊艳的复赛作品。**

这就是V4.1最终技术基线。
